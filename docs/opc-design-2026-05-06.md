## 1. 问题陈述

### 1.1 核心痛点

OPC（一人公司）创业者在产品上线前，面临**40个核心节点**，每个节点都有大量未知：

- 创业想法验证：不知道自己的点子是否可行
- 工具选型：AI编码工具太多，不知道选哪个
- 公司注册：流程、政策、费用、经营范围选择
- 支付接入：微信支付、支付宝、聚合支付
- 合规风险：金税四期、无票支出、广告合规

现有解决方案的问题：

| 现状 | 问题 |
|:---|:---|
| 搜索引擎结果 | 碎片化、陈旧、不完整 |
| 付费中介 | 价格不透明、质量参差 |
| 社群分享 | 零散、无体系、难验证 |
| 工具文档 | 各自独立、无连通性 |

### 1.2 目标用户

**第一类：空白用户** — 有创业想法，但没有完整路径认知
- 典型：想创业但不知道从哪开始
- 痛点：需要「地图」，不知道自己缺什么
- 付费意愿：低单价开始，愿意为确定性付费

**第二类：进行中用户** — 已经开始创业，某个节点卡住
- 典型：注册公司卡了、服务器不会配
- 痛点：具体节点需要具体解法
- 付费意愿：愿意为解决当前问题付费

**第三类：效率用户** — 有经验，想降低时间和金钱成本
- 典型：已经创过业，想优化流程
- 痛点：现有方案太贵、效率太低
- 付费意愿：高，但要求明确ROI

## 2. 产品愿景

### 2.1 使命

**让一个人公司创业变得简单——从0到1的全流程节点导航。**

### 2.2 核心价值

不是「更好用的工具」，是「更完整的地图 + 可信赖的向导」。

### 2.3 核心原则

1. **绝对纯OPC**：删除所有需要员工、合伙人、融资的内容
2. **生死线前置**：所有能导致项目死亡的节点放在最前面
3. **严格线性**：按照"想法→工具→开发→注册→支付→上线→赚钱"顺序排列
4. **优先级明确**：前22个核心必做（30天走完上线赚钱），后18个扩展可选

### 2.4 差异化定位

| 维度 | 传统方案 | 我们的方案 |
|:---|:---|:---|
| 内容深度 | 单一工具的单一教程 | 全流程节点的系统百科 |
| 更新速度 | 月/季度更新 | AI实时监控，10分钟迭代 |
| 用户验证 | 无验证 | 社区贡献者+官方审核 |
| 服务模式 | 标准化产品 | 非标准化高接触服务 |

## 4. 页面结构

### 4.1 页面清单

| 页面 | 路由 | 描述 |
|:---|:---|:---|
| 落地页 | `/` | 节点百科首页，Linear风格全屏节点列表 |
| 节点详情页 | `/nodes/:slug` | 单个节点完整内容，AI生成 |
| 测试答题页 | `/test` | 10道OPC适配度测试题 |
| 结果页 | `/result/:id` | AI分析报告 + 分享/下载 |
| 服务市场 | `/services` | 付费服务列表 |
| 管理后台 | `/admin` | 查看测试结果和支付记录 |

### 4.2 落地页设计方向（Phase 1.5）

**Linear App风格**：
- 全屏节点列表，按分类分组
- 节点之间有视觉连接线
- 每个节点可独立展开详情
- 左侧分类导航，右侧节点内容

## 5. 技术架构

### 5.1 技术栈

| 层级 | 技术 |
|:---|:---|
| 前端 | Vanilla JS + Tailwind CDN |
| 后端 | Node.js + Express |
| 数据库 | JSON文件存储 |
| AI | DeepSeek V4 Flash (腾讯TokenHub) |
| 支付 | 微信支付 (人工确认) |

### 5.2 路由设计

```
/                           → index.html (落地页)
/nodes/:slug               → 节点详情页
/test                      → OPC适配测试
/result/:id                → 测试结果页
/services                  → 服务市场
/admin                     → 管理后台
```

### 5.3 API设计

| 端点 | 方法 | 描述 |
|:---|:---|:---|
| `/health` | GET | 健康检查 |
| `/api/nodes` | GET | 获取所有节点 |
| `/api/nodes/:slug` | GET | 获取单个节点 |
| `/api/analyze` | POST | OPC适配度分析 |
| `/api/generate-node-content` | POST | AI生成节点内容 |
| `/api/confirm-payment` | POST | 支付确认 |
| `/api/stats` | GET | 统计数据 |

## 6. 设计系统

### 6.1 色彩系统 (Ma 墨色暗色模式)

| Token | 色值 | 用途 |
|:---|:---|:---|
| `--bg` | #111110 | 页面背景 |
| `--surface` | #1A1A18 | 卡片/模态框背景 |
| `--text-primary` | #F0EDE6 | 主要文字 |
| `--text-secondary` | #7A7670 | 次要文字 |
| `--accent` | #C0392B | 朱红强调色(最多1处/页) |
| `--line` | #2A2A28 | 分隔线/边框 |

### 6.2 字体系统

| 用途 | 字号 | 字重 |
|:---|:---|:---|
| Display | clamp(2.5rem, 12vw, 8rem) | 200 |
| Headline | clamp(1.125rem, 5vw, 1.75rem) | 300 |
| Body | 0.9375rem | 400 |

### 6.3 禁止的设计模式

- 圆角药丸按钮 (border-radius: 0 或 max 2px)
- 原色CTA (蓝/绿按钮)
- 玻璃拟态/背景模糊
- 对称三列卡片网格
- 引人注目的弹跳/弹簧动画
