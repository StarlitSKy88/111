服务器安全防护

防火墙配置、安全监控、漏洞修复，网站上线后就应该做

本章速读
  • 目标：在网站正式上线当天，就把服务器防护从"裸奔"升级到"基础免疫"，挡住 80% 自动化攻击。
  • 你要做的事：3 步：① 启用云厂商 WAF + 免费证书 → ② 关闭所有非必要端口 → ③ 接入日志告警（异常登录/异常流量）。
  • 不需要会：不需要专业安全工程师，不需要买昂贵硬件防火墙，不需要自建 SOC 平台，云厂商控制台已够用。
  • 本章产出：1 张《端口暴露清单》+ 1 份《WAF 规则集》+ 1 份《告警联系人与升级 SOP》。
D1 核心 本质

OPC的安全现实

一人公司 = 所有鸡蛋放一个篮子，且没有备份方案。攻击面极窄，但一次被破 = 业务终结。

AI驱动的自动化攻击：当前生成式AI让扫描器可以7×24无差别遍历全网。弱口令、未打补丁的Redis/SSH，平均存活时间已降至数小时。

合规义务下沉：《个人信息保护法》对处理个人信息的自然人同样适用。无论规模，只要收集手机号、邮箱或行为数据，就必须具备基本技术措施。

平均存活时间 数小时
攻击来源 自动化扫描
恢复目标 ≤30分钟
× 错误示范
"我只个小站，没人会攻击我"——攻击者用AI全天候扫描，不挑目标大小，只看有没有漏洞。
D2 模型

范式一：无服务器全托管

2026年，自己维护服务器 = 承担半全职安全运维工作量。更务实的做法是迁移到"无服务器"或"后端即服务"架构。

前端
Vercel / Netlify / Cloudflare Pages
全球边缘分发、自动HTTPS、WAF一体化，无需关心Nginx配置
后端
Cloudflare Workers / Vercel Edge Functions
函数层级写代码，运行环境由平台隔离加固，攻击面锁定在沙箱内
数据
PlanetScale / Supabase / Neon
Serverless数据库，自带每日备份，连接管理、防火墙策略完全托管
存储
对象存储 + CDN签名URL
不再自建FTP或文件服务器，用云存储代替
✓ 正确示范
使用全托管架构后，服务器级安全事件概率下降约78%，处理时间从4.2小时降至15分钟以下。
安全责任转移 平台承担OS层
你仍需保护 平台账号本身
D3 培育

范式二：韧性取代绝对安全

一人公司没有24小时值守安全团队。理性目标不是"不被攻破"，而是"被攻破后能多快恢复"。

可以没有专职安全人员，但不能没有安全基线；可以接受攻击尝试每天都在发生，但不能接受被攻破后毫无恢复能力。

三大工程实践：

1
基础设施即代码(IaC)
用Terraform/Pulumi声明环境，Git仓库管理。服务器被篡改后，10分钟内从零重建完全相同的环境。
2
不可变备份与恢复演练
Object Lock/WORM存储，7天内备份无法被删除或篡改。每月执行一次完整恢复演练，目标是低于30分钟。
3
无状态化设计
用户会话、缓存、上传文件全部外移到托管Redis/对象存储/数据库，服务实例可随时销毁替换而不丢失数据。
✓ 正确示范
你不再追逐零日漏洞防御，而是确保入侵发生后，服务能在30分钟内重生。这种能力远比WAF更能抵抗不确定性。
◑ 核心转变
从"建高墙"到"做好回滚"。防御重心从"加固服务器"转移到"加固代码和身份边界"。
D4 避坑

10分钟安全加固

不需要成为安全专家。用免费工具构建非对称防御，让自动化攻击绕道而行。

1
接入Cloudflare（免费）
将域名DNS解析权交给Cloudflare，开启代理(橙色云朵)。自动隐藏源站IP，拦截SQL注入/XSS，DDoS无限量免费缓解。
2
关闭所有入站管理端口
SSH/RDP/数据库端口绝不暴露公网。使用Cloudflare Tunnel或云厂商堡垒机代替直接登录。
3
强制密钥登录，禁止密码
服务器SSH禁用密码，使用Ed25519密钥对。私钥存1Password，每90天轮换。
4
GitHub密钥扫描
开启GitHub Advanced Security的密钥检测，每次推送前自动扫描，发现泄漏立即阻断并告警。
× 致命操作
把SSH/RDP端口直接暴露公网 + 弱密码。这等于在暗网挂牌出售服务器权限。
✓ 域名安全
开启注册商锁定(Registry Lock)和转移锁定(Transfer Lock)，防止域名被静默转走。

一、2026年OPC的最低安全基线

五条不做就会死的安全规则

规则不做会怎样
**SSH禁用密码登录，只用密钥**被暴力破解→服务器变矿机
**所有对外服务只开必要端口**多余的端口=多余的攻击面
**数据库不暴露在公网**被拖库→用户数据泄露
**HTTPS强制启用**中间人攻击→用户密码被窃
**定期更新系统和依赖**已知漏洞被利用→入侵

二、30分钟完成基础加固

第1步：SSH加固（5分钟）

# 1. 生成本地密钥对
ssh-keygen -t ed25519 -C "你的邮箱"
 
# 2. 上传公钥到服务器
ssh-copy-id root@你的服务器IP
 
# 3. 禁止密码登录
sudo sed -i 's/#PasswordAuthentication yes/PasswordAuthentication no/' /etc/ssh/sshd_config
sudo sed -i 's/#PermitRootLogin yes/PermitRootLogin prohibit-password/' /etc/ssh/sshd_config
sudo systemctl restart sshd

第2步：防火墙配置（5分钟）

sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22    # SSH
sudo ufw allow 80    # HTTP
sudo ufw allow 443   # HTTPS
sudo ufw enable

第3步：自动安全更新（2分钟）

sudo apt install -y unattended-upgrades
sudo dpkg-reconfigure unattended-upgrades  # 选"Yes"

第4步：数据库安全（10分钟）

-- Supabase 的 Row Level Security 必须开启
ALTER TABLE users ENABLE ROW LEVEL SECURITY;
 
-- 每个表定义谁能读、谁能写
CREATE POLICY "用户读自己的数据" ON users
  FOR SELECT USING (auth.uid() = id);
 
-- 敏感字段不要返回给前端
-- 查询时永远不要 select * 如果包含密码/密钥字段

第5步：环境变量管理（3分钟）

# ❌ 绝不要在代码里写：
const API_KEY = "sk-xxxxx";
 
# ✅ 用环境变量：
const API_KEY = process.env.API_KEY;
 
# .env 文件必须加入 .gitignore
echo ".env" >> .gitignore
