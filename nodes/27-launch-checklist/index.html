节点27：上线前检查清单

节点 27 / 57 · 最后修订：2026年6月4日

node_id: 27

persona: neutral

cta_type: wechat

keywords: [上线, 检查, 清单, 发布, 最后]

上线 = 把"能跑"变成"能赚钱"。99% 的 OPC 在这一步发布后才发现一堆问题。本节点给你一份强制检查清单，发布前 1 小时逐项过。

一、上线前 24 小时的 4 个心态

  1. 不要慌 — 第一版一定不完美，发布后能修
  2. 不要全发 — 用灰度发布，先 10% 用户
  3. 不要裸奔 — 监控 + 日志必须有
  4. 不要闷头发 — 告诉 10 个朋友，让他们先用

二、技术检查（30 项核心）

性能

  • 首屏加载 < 3 秒（手机 4G 测）
  • 主要 API 响应 < 500ms
  • 图片压缩（用 WebP，平均 < 200KB）
  • 没有未压缩的 5MB+ JS bundle

安全

  • HTTPS 全站启用（不要 http 混合）
  • .env 没推到 GitHub
  • 数据库密码 > 16 位
  • 用户输入做 XSS 转义
  • 密码 bcrypt 加密
  • CORS 配置正确（不是 *）

监控

  • 错误日志上报（Sentry / 自建）
  • 服务可用性监控（UptimeRobot）
  • 关键操作埋点（注册、付费）
  • 数据库备份自动跑（每天 1 次）

用户体验

  • 404 页面有引导
  • 500 页面有"联系客服"
  • 注册流程 < 2 分钟
  • 关键按钮不挡广告法规要求位置
  • 暗色模式不强制

合规

  • 用户协议 + 隐私政策上线
  • 注册时有勾选"我同意"
  • 营业执照展示（公司主体）
  • 客服联系方式（微信/邮箱/电话）

三、内容检查（10 项）

  • 首页标题、描述、关键词正确
  • 落地页有明确 CTA（按钮文字清晰）
  • FAQ 至少 3 条
  • 帮助中心/About 页能打开
  • 没有占位符（"Lorem ipsum" / "TODO"）
  • 没有死链（点开都 200）
  • 移动端没明显错位
  • 所有图片有 alt 文字

四、运营检查（5 项）

  • 客服微信二维码在 footer
  • 至少有 1 篇产品介绍（公众号/知乎）
  • 5-10 个种子用户名单
  • 上线当天能发朋友圈/小红书
  • 监控 24 小时在线（特别是前 12 小时）

五、上线当天的时间表

时间动作
09:00部署到生产环境
09:30自己用 1 小时，测所有核心流程
10:3010% 灰度放行（如有灰度功能）
11:00通知 5-10 个朋友开始用
14:00看监控，看反馈
18:00处理反馈 + 紧急修复
22:00全量发布 / 或第二天发

六、3 个常见上线事故

事故 1：忘记清 console.log

症状：生产环境 console 被刷爆，怀疑被攻击。 解法：上线前 grep console.log 全部删掉或用工具移除。

事故 2：数据库连接池太小

症状：10 个用户同时在线就 500。 解法：连接池 ≥ 20，并发量 > 100 时升级。

事故 3：CDN 缓存了 404

症状：改完代码没生效，刷新几次才好。 解法：CDN 配 0 缓存或加版本号 query。

七、检查清单

  • 30 项技术检查全过
  • 10 项内容检查全过
  • 5 项运营检查全过
  • 上线当天时间表已排
  • 紧急联系人清单（域名、服务器、CDN）
  • 准备好 24 小时值守
