节点 04 · 产品验证

产品原型设计

你不会用Figma、不会画UI、不知道什么叫"设计规范"。没关系——原型不是设计稿，原型是"让你的脑袋里的想法变成别人能看懂的东西"。本章零设计基础，30分钟出第一版原型。

为什么OPC必须做原型
核心认知
原型是"你脑子里的产品"和"AI写出来的产品"之间的翻译层。

原型只有一个目的：让一个完全不了解你产品的人，看了之后能在10秒内说出"这个东西是用来干嘛的"。

直接写代码 先做原型
写了3天代码发现页面跳转逻辑不对 10分钟纸笔画出问题，改两笔就行
做完给朋友看，朋友说"这按钮在哪" 原型阶段就发现入口不明显
需求改了，前端代码废掉一半 纸上擦掉重来，零沉没成本
喂给AI开发时描述不清楚 一张原型截图+prompt，AI直接理解
纸笔原型法：比任何软件都快
1
画方框
在一张纸上画一个手机屏幕大小的矩形。在里面画3-4个方框——这是你产品的核心区域。不用画任何细节。方框就够了。
2
写按钮名
在每个方框旁边写一句话，说明这个方框里会发生什么。比如："用户点这里上传文件"、"这里显示分析结果"、"点这里付款"。
3
画箭头
用箭头把方框连起来，表示用户的操作流程。
[首页] → [上传文件] → [分析中] → [查看结果] → [付款]
4
标注3个按钮
用红笔圈出最核心的3个按钮。问自己：用户第一眼能看到它们吗？如果用户10秒内找不到——按钮位置不对。
5
拍照
用手机拍下这张纸。这就是你的第一版原型。

2024年，一位深圳独立开发者想做小红书数据分析工具。他在咖啡馆餐巾纸上画了三个页面，照片发到即刻上配文"打算做这个，需要的人扣1"。2小时内72个回复。他周末两天用Cursor写出了第一版。如果先写代码再找用户——他可能花两周才发现需求根本不对。

Figma入门：8步出可交互原型
为什么是Figma
免费且国内可访问
个人用户免费，最多3个项目
浏览器运行，不需要安装
国内可直接访问
AI友好：Figma截图喂给AI能直接生成代码
8步总耗时
约15分钟
第一次可能30分钟
跟着做就能完成
不需要任何设计基础
只需要会上网
1
注册（1分钟）
打开 figma.com → 点击"Get started for free" → 用Google/邮箱注册 → 选择"Personal"免费计划。
2
新建Frame（30秒）
点击左上角"Design file"新建文件 → 按键盘 F → 右侧面板选"iPhone 15 Pro"（或你目标用户最常用的设备尺寸）。
3
画矩形（1分钟）
按键盘 R（矩形工具） → 在Frame里拖出一个矩形。这是你的一个页面区域。再按 R 多画几个矩形——每个矩形代表一个内容模块。
4
加文字（2分钟）
按键盘 T（文字工具） → 点击任意位置输入文字。不用管字体、字号、颜色。你需要写的文字只有：页面标题、按钮文字（比如"上传文件""立即购买"）、每个模块的简短说明。
5
改颜色（1分钟，可选）
选中任意矩形 → 右侧面板 Fill → 点颜色块 → 选一个颜色。OPC配色建议：背景用白或极浅灰，主按钮用一个鲜明颜色（比如蓝 #3B82F6 或红 #C0392B），文字用黑。
6
复制页面（30秒）
在左侧图层栏，选中你的Frame → Ctrl/⌘ + D 复制一份。在复制出的第二个Frame里，改成另一个页面的内容。每个页面一个Frame。一个简单产品通常3-5个页面。
7
加交互连线（3分钟）
切换到"Prototype"模式（右上角标签）。点击第一个页面上的按钮 → 拖出蓝色的线 → 连到第二个页面。弹出的面板里选 "On click" → "Navigate to"。这样在预览模式下，点击按钮就能跳转到对应页面。
8
手机预览（1分钟）
安装 Figma 手机APP（iOS/Android都有）。在手机APP上打开你的文件 → 点击"播放"按钮 → 就可以像真App一样操作你的原型。发给朋友测试：让对方在手机上操作，你在旁边看——一句话都不要解释。如果对方卡住了——那是原型的问题，不是对方的问题。
一页原型自检清单

把原型摆在面前，问自己这5个问题。5个都是绿灯才可以开始开发。有任何一个是红灯，修改原型。

# 问题 绿灯标准 常见问题
1 用户能在10秒内看懂这页是干什么的吗？ 不解释，对方直接说"哦这是做XX的" 标题太业余、布局混乱
2 核心按钮在首屏看得见吗？（不用滚动） 打开页面第一眼就能看到 按钮太小、颜色和背景太接近
3 从进入产品到完成核心操作，点击次数 ≤ 3次吗？ 首页 → 核心页 → 结果页，三页闭环 中间塞了太多设置页
4 原型上的文字用户能看懂吗？（不是"你"能看懂） 没有行业黑话、没有"系统将为您" "输入分析参数""立即查询" vs "粘贴链接""一键分析"
5 用手机打开原型，手指能点到所有按钮吗？ 按钮至少 44×44 像素（指甲盖大小） 桌面做得好看，手机上点不到
三平台设计规范速查

不同平台的原型，有些规则是硬性的（审核不通过）。OPC实战速记：Web优先最自由，小程序最严格，App建议一个平台做成熟了再做另一个。

规范项 Web 微信小程序 移动App
最小触控区 无硬性规定（建议 44×44px） 必须 ≥ 44×44px（微信审核硬性要求） iOS: 44×44pt, Android: 48×48dp
导航方式 顶部导航栏 + 底部可选 底部TabBar必须2-5个，每个图标+文字 iOS: TabBar / Android: 底部导航或侧边抽屉
安全区 浏览器视口内 顶部状态栏 + 底部Home指示条（iPhone X以上机型）注意避开 顶部刘海区 + 底部手势条区不可交互
返回逻辑 浏览器自带返回 左上角必须有返回按钮，或安卓实体返回键 iOS左滑返回，Android返回键
字体 不限 必须用系统默认（iOS苹方/Android思源），不可用自定义web字体 系统默认
启动页 无 必须有（可在后台配置，尺寸 430×932px） iOS要求Launch Screen，Android要求Splash Screen
分享 链接复制 分享按钮强制在右上角（微信规定） 各平台自由设计

总纲

原型不是设计——原型是沟通工具。它是OPC和AI之间的共同语言。

三步出原型
1. 纸笔（10分钟）→ 确认方向对不对
2. Figma（30分钟）→ 确认交互顺不顺
3. 喂给AI（5分钟）→ 变成可以运行的代码

原型的目的是被推翻。不要花2天画一个"完美"的原型——那你会不敢改它。
（本文写于2026年5月。Figma界面可能持续更新，但核心操作逻辑长期不变。）

2026 UPDATE
**面向OPC**：你有一个想法，但你不能花三个月把它做出来才发现没人要。原型的作用是：用最短的时间，做出"看起来像真的"的东西，拿去给别人看，收集反馈，再决定做不做。

三、OPC原型设计三原则

1. 只画核心流程

不是把所有页面都画出来，只画用户完成核心任务的那条路径。

例：一个AI简历优化工具
只画：首页 → 上传简历 → 查看优化建议 → 下载优化版
不画：设置页、个人中心、历史记录、付费页面（原型阶段不考虑）

2. 用真实内容，不用"Lorem Ipsum"

假文字（"标题标题标题"）让人无法判断产品价值。用真实场景的内容。

3. 原型做完当天就拿给人看

不要打磨原型。粗糙但能传达想法的原型 > 精美但一周后才拿出来的原型。

四、从原型到验证的完整流程（2026年）

Day 1 上午: Excalidraw画核心流程（30分钟）
Day 1 下午: 用v0.dev/bot.new生成可点击版本（2小时）
Day 1 傍晚: 发给3个朋友，问"你看懂这是什么了吗？"
Day 2: 根据反馈修改 → 再发给2个目标用户
Day 3: 决定：做 / 改方向 / 放弃

铁律：原型阶段超过3天=你在做产品，不是在验证想法。

五、检查清单

  • [ ] 核心流程已画出（不是全部页面）
  • [ ] 原型中有真实内容（非Lorem Ipsum）
  • [ ] 至少3个人看过原型
  • [ ] 收集了"看不懂的地方"和"愿意用吗"的反馈
  • [ ] 3天内做出了Go/No-Go决策
