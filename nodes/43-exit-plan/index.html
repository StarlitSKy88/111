节点内容

退出准备：资产的"去个人化"剥离

退出交易的本质，是在出售一个脱离了你依然能运转的系统。超过半数的OPC退出失败案例，并非价格谈不拢，而是买方尽调后发现资产与创始人个人账户过度捆绑。

第一阶段：财务与账户的物理切断

公私混同是最致命的合规红线

新《公司法》强化了对"实质一人公司"的穿透审查。必须将项目所有收入切换至独立对公账户，过往个人微信、支付宝收款历史必须导出完整流水并补开合规发票。服务器、API调用费、域名续费等运营成本必须从项目独立账户支出，严禁混合支付。

第二阶段：数字资产的清点与权限集中

无形资产三件套

代码与数据权属：私有数据集和大模型微调权重已成为核心议价点。
社媒与分发渠道：订阅号、App Store开发者账号的所有权，若无法变更估值折价30%。
合约权利转让：含有"主体变更即违约"条款的合同，必须先行取得客户书面谅解。

第三阶段：核心能力的AI文档化封装

制作"AI可读操作包"

录制决策逻辑：把每日判断"何时投流、何时关停、如何回复复杂客诉"的思维过程转化为结构化决策树。
沉淀运营提示库：整理处理业务的全部Prompt指令。一份高质量AI指令集可直接带来10%-15%的溢价。

错误示范

未完成财务切断就接触买家

认为"找到买家再清理账目也不迟"。新买方律师会重点核查公私混同，若无法做出清晰切割，交易对手不仅会压价，更可能设置24-36个月的历史债务追索条款。

错误示范

把"买代码"当成退出唯一形式

忽视"隐性知识"的价值交付。买家真正收购的是一个可立即投入运营的"微型盈利系统"：客户列表、自动化SOP、专属数据集。只交付代码但不交付运营逻辑，估值至少打5折。

正确示范

原子化资产交付

使用具备存证功能的智能合约进行权限交接，留有不可篡改的时间戳。Loom视频库或AI可解析SOP文档作为尾款释放条件，在尾款确认到账瞬间移交。

2026 UPDATE
**面向OPC**：不是每个项目都要做一辈子。知道什么时候该坚持、什么时候该放手、什么时候该卖掉——这是OPC最重要的决策能力之一。本节点告诉你2026年OPC的四种退出方式。

一、退出不是失败

先纠正一个认知

你以为的退出实际上的退出
失败、放弃、丢人资源重新配置、止损、为下一个项目腾出精力
项目死了经验留下了
白干了你用X个月买了一个别人没有的经验

2026年最成功的OPC们，平均经历过2.3个"失败"项目才找到那个赚钱的。

二、四种退出方式

方式1：关停（最快，最常用）

什么时候该关停：

信号标准 连续亏损6个月总收入<总支出 用户不增长连续3个月月活无增长 你不想做了打开代码都觉得痛苦（持续1个月以上） 更好的机会来了有一个明确更赚钱/更有意义的方向

关停的正确姿势：

1. 给现有用户发一封邮件/公告："XX产品将于X月X日停止服务。数据可在X月X日前导出。感谢你的支持。"

2. 导出所有数据备份（留作纪念和复盘）

3. 写一篇复盘文章：《我做了X个月的产品为什么失败了》→ 这篇文章可能比你产品赚得还多（行业内有大量失败复盘文章的阅读量>10万）

方式2：卖掉（最赚钱，最难）

2026年OPC产品能卖多少钱：

产品状态估值范围在哪卖 有用户无收入¥5000-20000Acquire.com, 即刻/推特发帖 月收入¥1000-5000年收入×1-2倍Acquire.com, Flippa 月收入¥5000-20000年收入×2-3倍MicroAcquire, 私下 月收入>¥20000年收入×3-5倍投资人/同行直接联系

2026年OPC产品交易平台：

  • [Acquire.com](https://acquire.com) — 全球最大的小微SaaS交易市场
  • [Flippa](https://flippa.com) — 适合内容站/电商/小工具
  • 即刻/推特发帖 — 中文独立开发者圈内交易
  • 2026年更新

卖掉前要准备的：

  • 6个月的收入数据截图
  • 用户数和增长曲线
  • 技术栈文档（买家要能接手）
  • 为什么卖的真实原因（买家会问）

方式3：转为副业（最温和）

产品不赚钱但用户还在用 → 不关停，也不全力做。

转为副业的操作：
1. 服务器降到最低配置（月费¥24）
2. 关闭需要人工介入的功能（如客服咨询）
3. 设置自动回复："这个产品目前由我一个人维护，回复可能较慢"
4. 每个月花1天看看运行状态
5. 把90%的精力投入下一个产品

方式4：开源（最有长期价值）

产品不赚钱但对社区有价值 → 开源。

# 1. 清理敏感信息
git filter-branch --force --index-filter \
  "git rm --cached --ignore-unmatch .env" --prune-empty -- --all
 
# 2. Push到GitHub Public
git remote add public https://github.com/你的用户名/项目名.git
git push public main
 
# 3. 写README（为什么做、怎么用、为什么不做了）
# 4. 在V2EX/即刻/推特宣布开源

开源的价值：GitHub上的开源项目=你的永久技术名片。很多OPC的下一个客户/合伙人，是通过他的开源项目找到他的。

三、退出决策框架

每个季度问自己一遍：
□ 这个产品还在增长吗？（用户数/收入/我的兴趣）
□ 如果今天重新选择，我还会做这个产品吗？
□ 我花在上面的时间，如果用来做别的，会不会更好？
 
如果有2个以上"否" → 认真考虑退出。

四、检查清单

  • [ ] 已明确当前产品的退出标准（什么时候该关/卖/开源）
  • [ ] 产品数据有定期备份
  • [ ] 用户数据导出功能可用（关停时用户要能拿走自己的数据）
  • [ ] 如果卖：6个月财务数据已整理
  • [ ] 如果开源：敏感信息已清理
