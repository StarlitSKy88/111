数据展示与交互

节点 14 / 57 · 最后修订：2026年5月11日

你做了功能，也存了数据，但用户打开页面看到一堆文字和数字就跑。怎么用最少的代码，让数据"自己会说话"？

一、OPC的数据展示第一原理

一个残酷的事实

用户在页面上停留的前3秒决定去留。3秒内没看懂的页面 = 用户关掉。

OPC的独特优势：你不是大公司，不需要做"数据大屏"。你只需要让用户看懂一个数字 + 一个趋势。

黄金公式

> 好的数据展示 = 1个大数字 × 1个趋势图 × 0个多余元素

  • 大数字：48px以上，放在页面最上方，一眼看到
  • 趋势图：一个简单的折线图或柱状图，展示"在变好"
  • 0个多余：不要筛选器、不要导出按钮、不要对比视图
反面案例：某OPC做了一个数据分析页，有7个筛选器、4种图表、3个导出格式。上线后DAU为零——因为用户打开页面后不知道看哪里。 正面案例：同样是这个OPC，把数据页砍到只剩"本周收入 ¥1,247"一个大数字 + 一个7天收入折线图。DAU翻了三倍。

三、图表选择决策树（实战版）

`

用户想看什么？

│

├─ 看变化 → 折线图（时间轴X，数值Y）

│ 例：过去30天注册人数变化

│

├─ 看排名 → 横向柱状图（长条目容易读）

│ 例：各功能使用次数排名

│

├─ 看占比 → 只展示TOP3 + "其他"

│

│ 例：本月总收入 ¥12,847

│

└─ 看对比 → 两个大数字并排

五、交互设计的最小必要集

永远要加的三个交互

  1. 点击数字看详情：大数字必须是可点击的，点了展示明细列表
  2. 图表hover提示：鼠标悬停显示具体数值（chart.js 默认就有）
  3. 空状态设计：新用户没有数据时，显示"完成第一次XX后这里会出现数据"，而不是空白页

永远不要加的三个"功能"

  1. ❌ 日期选择器：90%用户只用默认的"最近7天"和"最近30天"，放两个切换按钮即可
  2. ❌ 导出CSV/Excel：第一版不要做，等有用户明确要了再说。这一项能省你半天开发时间
  3. ❌ 自定义看板/拖拽布局：功能堆砌，OPC第一版不需要

六、移动端适配（一个人也要做）

OPC的产品50%以上的流量来自手机。数据页面在手机上出问题 = 丢掉一半用户。

响应式三原则

桌面端移动端
4列卡片并排2列卡片（或上下堆叠）
图表宽600px图表占满屏幕宽度
大数字48px大数字36px（仍然足够醒目）

一行代码搞定移动端图表

`css

/* Chart.js 自动响应式 */

canvas { max-width: 100%; }

/* Recharts 响应式容器 */

``

七、检查清单

  • 页面核心是一个大数字（≥36px移动端 / ≥48px桌面端）
  • 只有一个趋势图（折线或柱状），没有多余图表
  • 没有日期选择器、导出按钮、自定义布局
  • 空状态有引导文案
  • 图表hover能看具体数值
  • 手机横屏/竖屏都正常显示
  • 页面加载≤2秒（图表CDN引入，非打包）
