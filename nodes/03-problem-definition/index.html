问题定义与用户调研

62%的一人公司在18个月内注销——大多数不是败于市场，而是败于从未验证过"我解决的是不是真问题"。本章不教问卷调查、不教SPSS分析——只教一套一个人72小时内就能完成的验证方法。

一、为什么用户访谈是OPC的生死线

国内OPC最常见的死法

死法占比估计根本原因
做了没人用的产品~40%凭"我感觉"做功能，没问过用户
方向对但解法错~30%问了用户，但问法有诱导性
有用户但价格错~20%没验证用户"真掏钱"的意愿
其他~10%法律、资金、技术等

核心问题不是"会不会做"，而是"有没有搞清楚到底该做什么"。

一个真实国内案例：微信红包

2014年春节，微信红包团队做了一件事——他们没去设计"觉得用户会喜欢"的功能，而是在广东地区观察春节期间人们真实的红包行为：

① 广东人过年发红包有"利是"传统（小额、高频）
② 人们在微信群里的自然行为已经是"抢红包"（拼手气群接龙）
③ 问题不是"怎么发红包"，而是"线下的红包怎么搬到线上还能保持那个感觉"

他们把观察到的问题定义为："让用户在微信群里体验到和线下收红包一样的快乐"。然后才做了拼手气红包——不是先想功能再找用户，而是先看懂用户再想功能。

OPC的铁律

你的第一个版本，不应该超过5个人反复跟你聊过之后你才确定的。

二、10人1对1访谈法：OPC专属执行版

为什么是10人不是100人

Jakob Nielsen（尼尔森诺曼集团创始人）的研究表明：5个用户就能发现85%的可用性问题。 10个人足以覆盖你目标用户的绝大多数行为模式。

对OPC来说，10人访谈 = 你可以在一周内完成的验证规模。不需要问卷星、不需要广撒网——你一个人打电话、面谈、微信语音，全搞定。

执行六步

第1步：定义你的"问题假设"（30分钟）

在找人之前，先用一句话写下你的假设：

"我观察到[某类人]在[某个场景下]做[某件事]的时候，最困扰的是[某个问题]。"

真实示例（国内OPC场景）：

不好的假设好的假设
"小企业需要CRM""我观察到三线城市的建材批发店主，每天用微信手动回复几十个客户的询价，经常漏单、记错价格"
"年轻人需要理财""我观察到25-30岁的一线城市打工人，每月工资到账后不知道该怎么分配，余额宝利率越来越低但不敢碰基金"
"餐饮店需要小程序""我观察到二线城市社区周边的独立咖啡馆，美团抽成22%后几乎没利润，想建自己的渠道但不会做"

第2步：找到对的人（2小时）

你需要的不是"对品类感兴趣的"，而是"正在经历这个问题的"。

找人的渠道适合场景实操方法
微信朋友圈/群聊B2C、知识付费发一条动态："想聊一下[某话题]，请喝咖啡（¥30红包），限10人"
即刻/小红书私信年轻用户、兴趣社区搜索相关话题，找最近1周内发过相关内容的人私信
线下实地找人本地服务、实体店直接走进店里，点杯咖啡，跟老板聊10分钟
行业微信群B2B、垂直行业在群里发一个具体问题求助，私聊愿意回答的人
朋友的朋友所有场景让朋友介绍，比直接找陌生人转化率高3倍

关键原则：不要找你的朋友。朋友会出于礼貌说"挺好的"——这种反馈比没反馈更危险。

第3步：做访谈（每人30分钟）

铁律：

  • 不要解释你的产品
  • 不要问"如果有一个工具可以……"
  • 只问他们现在的行为、现在的痛点、现在的解决方案

第4步：记录（当场）

用手机录音（征得同意），但更重要的是当场记笔记——你会在当场捕捉到录音里听不出来的东西：对方说某句话时皱了一下眉头、停顿了3秒、突然提高了音量。

第5步：找出模式（访谈结束后2小时）

把10个人的访谈记录摊开，用荧光笔标注反复出现的词。如果10个人里有7个人不约而同地用了同一个词来形容他们的痛点——这就是你的产品应该解决的那个问题。

第6步：回到假设，修正或推翻（30分钟）

把你的原始假设和访谈结果对比。修正你的假设，或者——如果发现假设根本不对——果断放弃。这比做了半年产品才发现没人需要便宜得多。

四、从"我好烦XX"到真实需求的提取方法

用户说的 ≠ 用户需要的

经典案例：滴滴早期

2012年，程颐（滴滴创始人）自己在北京街头做了大量司机访谈。司机们说："最大的问题是找不到乘客。"但如果程颐直接做一个"帮司机找乘客"的工具，滴滴不会是今天的样子。

他多问了一层："除了找不到乘客之外，还有什么让你烦？"

司机说："最烦的是空车跑——不知道乘客在哪，跑过去发现人已经走了。"

核心需求不是"匹配司机和乘客"，而是"减少空驶率"。

提取公式

用户描述的表面行为 → 追问"为什么烦" → 找出真正的卡点
用户说不要理解为追问后会发现
"我每天要花2小时回微信群消息""他需要一个群管理工具"他的卡点是"怕漏掉付费客户的咨询，但又不想被闲聊打扰"
"记账好麻烦""他需要一个记账App"他的卡点是"年底报税时代账公司问我要数据，我根本找不到"
"小红书发笔记太花时间""他需要一个自动排版工具"他的卡点是"不知道怎么写标题才有流量，写了10篇只有2篇有人看"
"招聘太难了""他需要一个招聘平台"他的卡点是"收到200份简历但没有一份能用，筛选太浪费时间"

五个追问魔法词

当用户说"XX好麻烦/好烦/好难"时，用这五个词追问：

  1. "上次是？" → 把模糊抱怨变成具体场景
  2. "怎么解决的？" → 了解现有方案的缺陷
  3. "多久一次？" → 判断是高频痛点还是偶尔困扰
  4. "最坏会怎样？" → 衡量痛点的真实代价
  5. "试过别的吗？" → 了解竞品和替代方案

六、付费意愿验证：真金白银比承诺更诚实

为什么"我愿意付费"不可信

国内用户出于礼貌习惯性说"挺好的""应该会用"。这是OPC验证阶段的第一杀手。

数据

哈佛商学院研究——调查中表示"愿意购买"的用户，实际购买转化率仅为10%-20%。

三种真实验证方法

方法一：48小时预售页测试

做一个极简单页（用Trae或Canva），放上产品介绍 + 一个"预购"按钮。按钮链接到一个真实的收款页面（微信赞赏码/支付宝收款码）。

  • 发给你访谈过的10个人 + 朋友圈/社群
  • 48小时后看有多少人点了付款
  • 超过0人付款 = 信号成立（哪怕只有¥9.9）

国内真实案例：2023年，一位独立开发者做了一个"小红书文案AI辅助工具"。在写任何代码之前，他在即刻上发了一条动态：

"做了一个小红书爆款标题生成器，输入你的主题，帮你生成10个标题。预售¥9.9，限前50人，加我微信付款。"

48小时内37人付款。他花了3天写了第一版。如果没人付钱——他连3天都不会浪费。

方法二：虚假门测试

在目标用户聚集的地方发布一个"内测招募"，设置一个门槛：

"我们正在做一个[产品简述]，首期开放20个内测名额，需要填写申请表并支付¥1锁定名额（正式上线后抵扣¥20）。"

关键指标：登记率。如果看到信息的人里有超过20%填写了申请表——这比你问100个人"你会用吗"都更有说服力。

方法三：礼宾式交付

不做产品，先做服务。你本人充当产品的"AI引擎"，手动为前3个用户提供结果。

典型操作：

  1. 用户发来需求 → 你手动用ChatGPT处理 → 把结果发给用户
  2. 用户不知道背后是人工
  3. 观察：用户愿意为这个结果付费吗？用户会回来吗？

国内案例：某知识付费创作者想做一个"帮你写周报"的AI工具。他没有先开发——他在微信上对10个朋友说："每周五把你这周的工作要点发我，我帮你写周报，¥19.9/次。"做了4周，发现复购率为零——不是需求不对，是写周报这事一个月都不一定需要一次。他调整方向做了"帮你写晋升答辩PPT"——客单价¥299，复购（跳槽/年度述职）稳定。

七、创业想法筛选：三把刀

在10人访谈之外，用这三把刀筛一遍你的创业想法：

第一刀：认知套利能力

你的想法是否利用了你独有的认知积累——不是公开信息汇总，而是只有你（或极少数人）才有的洞察？
有认知套利无认知套利
你在某行业干了5年，知道客户最烦的3件事你看了几篇知乎就觉得自己懂了
你有一套独特的方法论（别人学不会或很难学）你的解决方案任何人花3天都能复制
你的经验/审美/判断力是核心壁垒你的核心价值是汇总公开资料

2026年已验证方向：实操材料包+加密教程——需要特定渠道才能获取的特殊材料 + 只能通过特定链接观看的详细视频教程。这种模式天然具备认知套利属性。

第二刀：抗AI替代性

你的核心价值是否容易被AI完全覆盖？
抗AI易被替代
深度情绪共鸣（心理咨询、占星、情感辅导）纯知识交付（问答、翻译、总结）
高度定制化策略（企业咨询、财税筹划）标准化内容生成
涉及物理世界（实物手作、线下体验）纯线上信息处理
需要真人信任背书（私域带货、保险）工具型SaaS（除非有独特数据壁垒）

第三刀：单人交付时间模型

这个生意的天花板是否在一个人可承受的范围内？

公式：

月收入上限 = 客单价 × (200小时 ÷ 单次服务耗时)

案例客单价获客+交付+售后月收入上限判断
工商注册代办¥2,0008h¥50,000可行
Web全栈开发¥30,00080h¥75,000单价高
个人简历修改¥2003h¥13,333天花板低
一对一英语口语¥1001.5h¥13,333手停口停

如果月收入上限低于你的生活成本 → 不可行。 要么提价、要么标准化、要么换方向。

八、三个必须停止的信号

当以下任一信号出现，果断终止，不浪费更多时间：

信号判断标准
获客成本 > 首单毛利你花在获客上的时间折算成工资，已经高于用户带来的利润
复购率趋近于零一人公司没有地推团队，老用户不回来意味着增长引擎一直熄火
需跨法律门槛需专职人员/前置行政许可证/大量固定资产 → 不符合OPC，及时转向

总纲

OPC失败的第一原因不是技术不行，不是运气不好，是花了一年做了一个没人需要的东西。

验证三步法：

  1. 10人访谈（一周内）—— 找出共同的痛点模式
  2. 48小时付费测试（两天内）—— 验证是否有人真掏钱
  3. 三刀筛选（一天内）—— 认知套利 × 抗AI替代 × 单人可交付

三关全过 → 进入MVP开发。任何一关不过 → 回到第一步，修正假设。
