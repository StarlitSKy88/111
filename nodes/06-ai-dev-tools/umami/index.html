Umami Analytics

隐私友好的网站统计工具。GDPR compliant，无 cookie，不追踪个人数据。自托管或云端使用，适合重视用户隐私的OPC项目。

分类：网站分析 · 隐私优先 · 开源免费
01 · 核心定位

什么是 Umami

Umami 是一款专注于隐私保护的网站分析工具，设计理念是"简单、透明、不侵犯隐私"。与 Google Analytics 不同，Umami 不使用 cookie，不收集个人身份信息，完全符合 GDPR、CCPA 等隐私法规要求。

核心优势：

✓ 无 cookie 设计，无需Cookie Consent弹窗

✓ 不追踪个人用户，尊重用户隐私

✓ 数据自托管，完全掌控

✓ 开源免费，生产可用

与 Google Analytics 对比

对比项 Umami Google Analytics
Cookie 使用 × 无 ✓ 必需
隐私合规 ✓ GDPR OK 需配置，复杂
数据存储 自托管/云端 Google 服务器
学习成本 简单 复杂
费用 免费/低成本 免费（但隐私代价）
数据控制 ✓ 完全掌控 受制于 Google

适用场景

个人项目/博客

轻量级统计，无需复杂配置，保护访客隐私

企业官网

展示型网站需要分析但不需要追踪用户行为

电商落地页

快速获取流量数据，优化转化率

内容型网站

了解读者来源，优化内容策略

02 · 快速上手

创建账号与获取追踪脚本

Umami 提供两种使用方式：云端版本（快速上手）和自托管版本（完全控制）。OPC 推荐先从云端版本开始，快速验证需求。

方式一：云端版本（推荐新手）

  1. 访问 umami.is 官网，点击 Get Started
  2. 使用 GitHub 或邮箱注册账号
  3. 创建第一个网站，获取追踪脚本
  4. 将脚本添加到网站 <head> 区域

方式二：自托管（技术用户）

需要准备：域名、服务器（1GB RAM即可）、 PostgreSQL 或 MySQL 数据库。

# Docker 部署方式 docker run -d \ --name umami \ -p 3000:3000 \ -e DATABASE_URL=postgresql://umami:umami@localhost:5432/umami \ -e APP_SECRET=your-secret-key \ umami-software/umami:latest

获取追踪脚本

在云端控制台创建网站后，你会获得一个类似这样的脚本：

<script async src="https://analytics.umami.is/script.js" data-website-id="xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"></script>

将这段代码添加到网站所有页面的 <head> 标签内，即可开始追踪。

提示：如果使用 Next.js/React，可以将脚本封装成组件，放在 _app.tsx 或 layout.tsx 中全局加载。

04 · 网站配置

添加网站与安装追踪器

添加网站

  1. 登录 Umami 控制台
  2. 点击 Settings → Websites
  3. 点击 Add Website 按钮
  4. 填写网站名称和域名（仅填域名即可，如 example.com）
  5. 保存后获取追踪脚本

安装追踪脚本

方法一：HTML 直接嵌入

将追踪脚本添加到网站所有页面的 <head> 标签中：

<head> ... <!-- Umami Analytics --> <script async src="https://analytics.umami.is/script.js" data-website-id="xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"></script> </head>

方法二：React/Next.js 组件

创建 UmamiTrack 组件，封装追踪脚本：

// components/UmamiTrack.jsx export function UmamiTrack({ websiteId }) { useEffect(() => { const script = document.createElement('script'); script.src = 'https://analytics.umami.is/script.js'; script.async = true; script.setAttribute('data-website-id', websiteId); document.head.appendChild(script); }, [websiteId]); return null; } // 使用 function App() { return ( <div> <UmamiTrack websiteId="your-id" /> {/* 其他内容 */} </div> ); }

方法三：npm 包方式（适用于 Next.js）

# 安装 umami tracker npm install @umami/umami-tracker-js # 使用 import { umami } from '@umami/umami-tracker-js'; umami.track('pageview', { url: '/home' });

验证安装

脚本安装后，访问网站并刷新 Umami 控制台，应该能在实时数据中看到访问记录。如果看不到：

  • 检查脚本是否正确添加到 <head> 区域
  • 确认 website-id 正确无误
  • 检查浏览器控制台是否有报错
  • 等待几分钟后数据刷新

06 · 隐私保护

隐私优先的设计理念

Umami 从设计之初就将隐私保护作为核心原则，这也是它与 Google Analytics 等工具的本质区别。

隐私保护措施

无 Cookie

不使用任何 cookie，不追踪跨会话的用户行为

匿名化处理

不收集可识别个人身份的信息（IP匿名化）

数据最小化

只收集必要的分析数据，不多收集

本地化存储

自托管版本数据完全存储在自己的服务器

合规认证

  • GDPR compliant - 符合欧盟通用数据保护条例
  • CCPA compliant - 符合加州消费者隐私法案
  • 不依赖第三方追踪
  • 可自定义数据保留期限

实际意义：

使用 Umami 意味着你的网站不需要显示恼人的 Cookie Consent 弹窗，不会被用户抱怨"为什么每个网站都要同意Cookie"，也不会因为隐私合规问题收到罚单。

数据安全性

自托管版本数据完全存储在自己的服务器：

  • 数据不经过第三方
  • 可设置数据自动清理策略
  • 完全掌控数据的所有权
  • 符合数据本地化要求（中国用户特别重要）

08 · 自托管部署

Docker 部署指南

自托管 Umami 需要准备 PostgreSQL 或 MySQL 数据库，推荐使用 Docker 简化部署流程。

环境要求

  • 服务器：1GB RAM + 10GB SSD
  • 数据库：PostgreSQL 12+ 或 MySQL 8+
  • Docker + Docker Compose
  • 域名（可选，用于HTTPS访问）

Docker Compose 部署

创建 docker-compose.yml：

version: '3' services: umami: image: umami-software/umami:postgresql-latest ports: - "3000:3000" environment: DATABASE_URL: postgresql://umami:your-password@db:5432/umami APP_SECRET: your-random-secret-key depends_on: - db restart: unless-stopped db: image: postgres:15-alpine environment: POSTGRES_DB: umami POSTGRES_USER: umami POSTGRES_PASSWORD: your-password volumes: - ./db:/var/lib/postgresql/data restart: unless-stopped

启动服务

# 启动所有服务 docker-compose up -d # 查看日志 docker-compose logs -f umami # 访问 # http://your-server-ip:3000 # 默认账号: admin / umami

Nginx 反向代理配置

为了支持 HTTPS 和域名访问，配置 Nginx：

server { listen 80; server_name analytics.yourdomain.com; location / { proxy_pass http://localhost:3000; proxy_set_header Host $host; proxy_set_header X-Real-IP $remote_addr; } }

数据备份

# 备份数据库 docker-compose exec db pg_dump -U umami umami > backup.sql # 恢复数据 cat backup.sql | docker-compose exec -T db psql -U umami umami

生产环境建议：

1. 使用 Docker Volume 持久化数据

2. 定期执行数据库备份

3. 配置自动更新（watchtower）

4. 启用 HTTPS（Let's Encrypt）

09 · 常见问题

FAQ

Umami 和 Google Analytics 哪个更好？

取决于你的需求。如果重视隐私、简单易用、无需复杂分析，Umami 是更好的选择。如果你需要高级分析功能、Google 系产品集成，Google Analytics 更强大。但代价是隐私和Cookie合规问题。

Umami 免费版有什么限制？

免费版每月 100,000 页面浏览量，3 个网站，5 个团队成员，30 天数据保留。对于大多数个人项目和中小网站来说足够了。

页面浏览量超出限额怎么办？

可以升级到付费版本，或者使用自托管方案。超出限额后数据仍会继续收集，只是仪表盘可能只显示部分数据。

自托管版本数据会丢失吗？

只要做好数据库备份，数据不会丢失。建议设置自动备份策略，每天备份一次数据库。

Umami 能追踪国内用户吗？

可以。但需要注意：如果使用云端版本，追踪脚本加载需要连接 Umami 服务器，可能会有加载失败的情况。建议国内用户使用自托管版本，部署在国内服务器上。

如何查看访客的详细信息？

Umami 设计理念是隐私优先，只收集聚合统计数据，不追踪单个用户的行为历史。如果需要更详细的用户追踪，需要考虑其他方案。

可以在同一个账户下管理多个网站吗？

可以。云端版本免费版支持3个网站，Pro版无限网站。自托管版本没有网站数量限制。

Umami 支持中文界面吗？

支持。Umami 社区提供了多语言支持，包括中文。在设置中可以切换语言。

总结

Umami 是一款专注于隐私保护的轻量级网站分析工具，适合 OPC 项目使用。它的优势在于：

  • 无需 Cookie Consent，隐私合规
  • 界面简洁，数据一目了然
  • 开源免费，自托管成本低
  • 部署简单，技术门槛低

推荐先用云端版本快速上手，有需求再迁移到自托管。
