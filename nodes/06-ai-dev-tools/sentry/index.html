06 / 开发工具 · Sentry

Sentry 教程

生产级错误监控平台。覆盖错误追踪、性能监控、崩溃分析、版本管理，让OPC在用户报Bug前就能发现并修复问题。

本教程适合零基础OPC，假设你已有基础的JavaScript/Node.js开发能力
一、核心定位

Sentry 对 OPC 的价值

Sentry 是一个实时错误追踪平台，被全球超过400万开发者使用。对于OPC而言，Sentry 是"24小时无休的 QA 团队"——它会在用户遇到错误时立即报警，并提供完整的上下文信息。

错误追踪

Error Tracking · 捕获生产环境异常

自动捕获前端和后端的未处理异常，提供完整的堆栈跟踪、浏览器信息、用户操作路径。用户在反馈问题前，你就已经知道了。

性能监控

Performance Monitoring · 发现慢查询

追踪请求链路，识别慢接口和数据库查询。知道哪个API响应时间最长，哪个操作让用户等待最久。

崩溃分析

Crash Analytics · 追踪App崩溃

iOS/Android原生App崩溃报告，关联到具体代码行。对于跨平台项目尤其重要。

版本关联

Release Tracking · 定位引入版本

通过版本号追踪每次部署后是否有新错误出现。哪个版本引入的Bug一目了然。

OPC 什么时候需要 Sentry？

1. MVP 第一次上线前（必须配置，不能裸奔）

2. 有用户开始使用你的产品

3. 有多个功能在并行开发

4. 想提前发现用户会遇到的问题

Sentry 解决的问题："用户遇到了错误，但我不知道"——这是每个开发者最头疼的问题。Sentry 让错误可见、可追踪、可复现。

二、快速上手

三分钟集成 Sentry

Sentry 的安装非常简单。以下以 JavaScript 为例，展示最基本的集成流程。

第一步：注册账户

访问 sentry.io，使用 GitHub 账号登录（最方便）。

注意：Sentry 官网在国内访问可能需要代理。如果无法访问，可以考虑国内的 阿里云日志服务 或 Bugly 作为替代方案。

第二步：创建项目

登录后点击 "Create Project"，选择你的技术栈。

# 创建 JavaScript (Node.js) 项目 # 1. 选择 Framework: Node.js # 2. 设置项目名称: my-opc-backend # 3. 获取 DSN (Data Source Name)

第三步：安装 SDK

npm install @sentry/node # 或前端项目 npm install @sentry/browser

第四步：配置 SDK

# sentry.js 或在你的入口文件中 import * as Sentry from '@sentry/node'; Sentry.init({ dsn: 'https://xxxx@sentry.io/xxxx', tracesSampleRate: 1.0, }); # 捕获未处理的错误 try { // 你的代码 } catch (err) { Sentry.captureException(err); throw err; }

DSN 是什么？

DSN (Data Source Name) 是 Sentry 识别你项目的唯一标识。在 Sentry Dashboard → Project Settings → Client Keys 中可以找到。格式如下：

https://[KEY]@[ORG].sentry.io/[PROJECT_ID]

这个 Key 是公开的，即使泄露也不会造成安全问题，因为 Sentry 的设计就是接收来自客户端的错误报告。

三、错误追踪

完整的错误上下文

Sentry 不仅仅是收集错误，还提供完整的调试信息，让你可以像在本地调试一样追踪线上问题。

堆栈跟踪 (Stack Trace)

每个错误都包含完整的调用堆栈，精确到源代码的具体行号。

# Sentry 捕获的错误信息包含 # - 错误类型: TypeError, ReferenceError, SyntaxError # - 错误消息: "Cannot read property 'x' of undefined" # - 文件路径和行号: /app/src/api/user.js:42:5 # - 调用堆栈: 完整的函数调用链 # - 原始代码片段: 出错那行代码的上下文

源映射 (Source Maps)

前端项目部署时通常会压缩代码，Sentry 支持上传 Source Maps 以显示原始代码。

# 安装 sentry-cli npm install sentry-cli --save-dev # 在构建脚本中添加上传命令 # package.json { "scripts": { "build": "webpack && sentry-cli releases files v1.0.0 upload-sourcemaps dist/" } } # 或使用 webpack 插件 import SentryWebpackPlugin from '@sentry/webpack-plugin'; module.exports = { plugins: [ new SentryWebpackPlugin({ release: process.env.RELEASE_VERSION, url: 'https://sentry.io', authToken: process.env.SENTRY_AUTH_TOKEN, project: 'my-project', org: 'my-org', }), ], };

用户上下文

通过设置用户上下文，可以在错误报告中看到是哪个用户遇到了问题。

# 设置当前用户信息 Sentry.setUser({ id: user.id, email: user.email, username: user.username, }); # 清除用户信息（用户登出时） Sentry.setUser(null);

自定义标签

添加自定义标签可以更方便地筛选和查找错误。

# 添加上下文标签 Sentry.setTag('version', appVersion); Sentry.setTag('environment', process.env.NODE_ENV); Sentry.setExtra('api_version', 'v2'); # 在捕获错误时附加额外信息 Sentry.captureException(err, { extra: { customData: '可以在此处附加任意数据', requestUrl: req.url, requestBody: req.body, }, });

错误追踪最佳实践：

1. 开启 Source Maps（前端必须）

2. 设置用户上下文（了解谁遇到了问题）

3. 关键位置手动捕获异常（try-catch）

4. 不要吞掉错误（至少要 Sentry.captureException）

四、性能监控

追踪请求链路

Sentry 的 Performance 功能可以追踪完整请求链路，帮助你发现性能瓶颈。

事务 (Transaction)

一个 HTTP 请求就是一个 Transaction，Sentry 自动追踪其生命周期。

# 自动追踪 Node.js 请求 import * as Sentry from '@sentry/node'; import { expressMiddleware } from '@sentry/node'; app.use(Sentry.Handlers.trpcHandler()); app.use(expressMiddleware());

慢查询检测

自动识别慢数据库查询和外部 API 调用。

# 手动创建 span 追踪自定义操作 const span = Sentry.startTransaction({ op: 'task', name: 'process-user-data', }); try { const result = await processUserData(userId); span.setStatus('ok'); } catch (err) { span.setStatus('error'); span.recordException(err); } finally { span.finish(); }
指标说明优化目标
P50中位数响应时间< 200ms
P9595%请求在此时长内完成< 500ms
P9999%请求在此时长内完成< 1s
Apdex用户满意度得分> 0.85

数据库查询监控

# 启用数据库慢查询追踪 import { makeNestableOpentracingDriver } from '@sentry/node'; const tracer = makeNestableOpentracingDriver({ dsn: process.env.SENTRY_DSN, slowDbThreshold: 100, // 超过 100ms 记录为慢查询 });

OPC 建议：性能监控的采样率不要设为 100%，线上流量大时会消耗过多配额。建议设置为 0.1（10%）或根据实际需求调整。

五、版本管理

追踪每次部署的影响

Sentry 的 Release 功能让你知道每个版本引入的 Bug 是新 Bug 还是老 Bug。

创建 Release

# 方式一：通过 sentry-cli 创建 sentry-cli releases new v1.0.0 # 方式二：在代码中创建 Sentry.init({ release: process.env.npm_package_version, }); # 方式三：通过环境变量 export SENTRY_RELEASE=1.0.0

关联 Commits

将 Sentry Release 与 Git Commits 关联，可以看到每次部署包含哪些代码变更。

# 上传 commit 信息 sentry-cli releases set-commits --auto v1.0.0 # 或手动指定 sentry-cli releases set-commits v1.0.0 --commit "my-org/my-repo@1.0.0..1.0.1"

部署时间线

Sentry 显示每个 Release 的时间线，可以看到：错误在哪个版本出现、哪个版本被修复、部署频率是否正常。

# 标记部署 sentry-cli releases deploys v1.0.0 new --env production # 完成 Release sentry-cli releases finalize v1.0.0

Release 工作流：

1. 代码合并到 main → 创建 Release

2. 部署到生产环境 → 上传 Source Maps + 标记 Deploy

3. 观察错误趋势 → 如果新版本错误增加，立即回滚

4. 下一版本 → 修复错误 + 创建新 Release

OPC 推荐方案

MVP 阶段（免费版）

用户 < 100，日错误 < 150

在产品初期，用户量不大，免费版足够使用。注意控制采样率，避免超额。

增长阶段（开发者计划）

用户 > 100，日错误 > 150

当产品开始增长，有一定用户基数后，升级到开发者计划解锁更多功能。

如何避免超额？

当错误数量接近限额时，Sentry 会发送警告邮件。建议：

  • 设置采样率 (tracesSampleRate: 0.1)
  • 忽略已处理的预期异常
  • 设置告警规则提前通知
  • 定期查看高频率错误并修复
七、SDK集成

多语言 SDK 示例

Sentry 支持几乎所有主流语言和框架。以下是常见场景的集成示例。

JavaScript (前端)

# 安装 npm install @sentry/browser # sentry.client.config.js import * as Sentry from '@sentry/browser'; Sentry.init({ dsn: 'https://xxx@sentry.io/xxx', integrations: [ new Sentry.BrowserTracing(), new Sentry.Replay(), ], tracesSampleRate: 0.1, replaysSessionSampleRate: 0.1, replaysOnErrorSampleRate: 1.0, }); # 手动捕获错误 try { await fetch('/api/user'); } catch (err) { Sentry.captureException(err); }

Node.js (后端)

# 安装 npm install @sentry/node # sentry.server.config.js import * as Sentry from '@sentry/node'; Sentry.init({ dsn: 'https://xxx@sentry.io/xxx', tracesSampleRate: 0.1, # 自动捕获未处理错误和未接受 Promise autoSessionTracking: true, }); # Express 中间件 import { expressMiddleware } from '@sentry/node'; app.use(Sentry.Handlers.requestHandler()); app.use(expressMiddleware()); app.use(Sentry.Handlers.errorHandler()); # 捕获异步错误 process.on('unhandledRejection', (err) => { Sentry.captureException(err); });

Python (Flask/Django)

# 安装 pip install sentry-sdk[flask] # Flask import sentry_sdk from sentry_sdk.integrations.flask import FlaskIntegration sentry_sdk.init( dsn='https://xxx@sentry.io/xxx', integrations=[FlaskIntegration()], traces_sample_rate=0.1, ) # Django pip install sentry-sdk[django] # settings.py import sentry_sdk from sentry_sdk.integrations.django import DjangoIntegration sentry_sdk.init( dsn='https://xxx@sentry.io/xxx', integrations=[DjangoIntegration()], )

Next.js 集成

# 安装 npm install @sentry/nextjs # sentry.client.config.ts import * as Sentry from '@sentry/nextjs'; Sentry.init({ dsn: process.env.NEXT_PUBLIC_SENTRY_DSN, tracesSampleRate: 0.1, }); # next.config.js const withSentryConfig = require('@sentry/nextjs/config')({ silent: true, }); module.exports = withSentryConfig({ // 你的 Next.js 配置 });

SDK 选择建议：优先使用官方 SDK，确保最佳集成。社区版本可能缺少最新功能或存在兼容性问题。

八、实战案例

OPC 典型集成场景

案例一 前端错误监控
# 场景：捕获 Vue/React 应用中的运行时错误 # sentry.config.js import * as Sentry from '@sentry/vue'; export function initSentry(app) { Sentry.init({ app, dsn: import.meta.env.VITE_SENTRY_DSN, integrations: [ Sentry.browserTracingIntegration(), Sentry.replayIntegration(), ], tracesSampleRate: 0.1, # 忽略某些预期错误 ignoreErrors: [ 'ResizeObserver loop limit exceeded', 'The user aborted a request', ], beforeSend(event, hint) { # 过滤敏感信息 if (event.request) { delete event.request.cookies; delete event.request.headers['authorization']; } return event; }, }); }
案例二 后端异常追踪
# 场景：Node.js Express API 的全局异常处理 # middleware/sentry.js import * as Sentry from '@sentry/node'; import config from '../config'; Sentry.init({ dsn: config.sentry.dsn, environment: config.env, release: config.version, tracesSampleRate: 0.1, }); export const sentryRequestHandler = Sentry.Handlers.requestHandler(); export const sentryErrorHandler = Sentry.Handlers.errorHandler({ # 过滤敏感数据 filter: (event) => { if (event.exception) { event.exception.values[0].stacktrace.frames.forEach(frame => { delete frame.vars; }); } return event; }, }); # routes/api.js import { sentryRequestHandler, sentryErrorHandler } from './middleware/sentry'; app.use(sentryRequestHandler); app.get('/api/users', async (req, res) => { try { const users = await UserService.getAll(); res.json(users); } catch (err) { Sentry.captureException(err, { extra: { requestId: req.id }, }); res.status(500).json({ error: 'Internal server error' }); } }); app.use(sentryErrorHandler);

九、常见问题

FAQ

Q: Sentry 的免费版有什么限制？

A: 免费版限制 1 个用户、每月 5,000 个错误事件、100,000 个性能采样点、数据保留 30 天。对于 MVP 阶段的 OPC 来说，这个额度通常够用，除非你的产品有严重的 Bug 导致错误量暴增。

Q: 如何减少错误事件数量？

A: 几个策略可以减少消耗：1) 设置采样率 tracesSampleRate: 0.1；2) 忽略预期异常（如用户取消请求）；3) 修复高频错误从源头解决问题；4) 使用 beforeSend 过滤不需要上报的错误。

Q: Sentry 会收集敏感数据吗？

A: Sentry 默认会收集请求头、Cookies、用户信息等。建议在 beforeSend 回调中过滤敏感数据。Sentry 不会自动上传文件或收集密码，但建议仔细审查上报的数据。

Q: 数据保留多长时间？

A: 免费版保留 30 天，付费版根据计划不同保留 30-90 天。如果需要更长的保留期，可以考虑导出数据到自有存储。

Q: 如何设置告警？

A: 在 Sentry Dashboard → Alerts → Create Alert 中配置。可以设置错误数量阈值、新错误出现时通知、某个标签的错误激增时通知。告警支持邮件、Slack、Discord 等渠道。

# 示例：设置错误率告警 # 当 5 分钟内错误数超过 10 或错误率超过 5% 时触发 # Alert -> Create Alert -> Error Rate # Environment: production # Threshold: 10 errors OR 5% of total transactions # Time window: 5 minutes # Channel: Email + Slack

Q: Source Maps 上传失败怎么办？

A: 常见原因：1) Token 权限不足（需要项目级写权限）；2) 文件路径不匹配（检查 --url-prefix 配置）；3) 构建产物路径变化（使用绝对路径）；4) Release 版本不匹配（确保版本号一致）。

Q: Sentry 会被墙吗？国内有没有替代？

A: Sentry 官网在国内访问不稳定。替代方案：Bugly（腾讯，专注移动端）、阿里云日志服务、FunDebug（国内专注前端监控）。

Q: 如何测试 Sentry 是否正常工作？

A: 在代码中手动触发一个测试错误：

# 浏览器控制台 Sentry.captureException(new Error('Test error from browser')); # Node.js throw new Error('Test error from server');

快速集成 Checklist

  • 注册 sentry.io 账户
  • 创建项目并获取 DSN
  • 安装对应 SDK (npm install @sentry/xxx)
  • 在入口文件初始化 Sentry.init()
  • 配置 tracesSampleRate (建议 0.1)
  • 上传 Source Maps（前端必须）
  • 设置用户上下文（可选但推荐）
  • 配置告警规则（错误数超阈值通知）
  • 测试验证（手动触发一个错误）

记住：Sentry 是 OPC 的"生产环境眼睛"。配置后，它会帮你发现用户遇到的每一个问题，让你在用户反馈前就能修复。
