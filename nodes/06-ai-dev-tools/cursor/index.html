06 / 开发工具 · 教程

Cursor AI IDE

AI-First代码编辑器。专为OPC设计的日常开发主力工具，项目级上下文理解，多文件协同编辑，智能化代码生成。

难度：入门级 | 优先级：P1（近期配置） | 预计时间：2小时
01 · 核心定位

为什么OPC需要Cursor

Cursor是当前最成熟的AI代码编辑器之一，它将AI能力深度融入开发工作流，让一个人公司也能高效完成全栈开发。

Cursor的核心价值：

不是替代程序员，而是成为程序员的"第二大脑"，处理重复性编码任务，让OPC专注于架构设计和业务逻辑。

项目级上下文理解

Cursor能理解整个项目结构、依赖关系、代码风格，不仅补全单行代码，而是理解代码意图后生成符合项目规范的多文件代码块。

日常开发工作主力

不同于Claude Code的CLI交互模式，Cursor是图形化IDE，深度集成VS Code生态，适合每天打开的项目。Tab补全、Composer批量编辑、Agent自主探索，三种模式覆盖日常开发场景。

中文友好界面

界面设计简洁直观，AI交互使用自然语言，中文Prompt效果优秀。OPC无需切换语言思维，直接用中文描述需求即可获得高质量代码。

成本可控的AI使用

内置模型切换功能，支持OpenRouter聚合平台。Pro版本$20/月，包含Claude 3.5 Sonnet、GPT-4o、Cursor Small等模型无限使用。

与Claude Code的区别

维度 Cursor Claude Code
交互方式 图形化IDE + 内联AI对话 CLI命令行
适用场景 日常开发主力，随时打开项目 复杂任务、自动化脚本、多步骤任务
代码编辑 多文件协同、Composer批量编辑 单次聚焦、快速修复
学习曲线 低，类VS Code体验 中，需要熟悉命令行
推荐用法 80%的日常编码任务 20%的复杂探索性任务

最佳实践：Cursor处理日常开发，Claude Code处理复杂任务。两者互补，Cursor为日常工作台，Claude Code为攻坚利器。

02 · 安装配置

快速上手

下载安装

访问Cursor官网下载对应系统版本。Cursor基于Electron，支持macOS、Windows、Linux。

# macOS brew install --cask cursor # Windows # 从官网下载.exe安装包 # Linux (Ubuntu/Debian) sudo snap install cursor --classic

首次启动配置

  1. 打开Cursor，进入欢迎界面
  2. 登录账号（推荐使用Google/GitHub授权）
  3. 选择配色方案（推荐Dark模式）
  4. 导入VS Code设置（如果之前使用VS Code）
  5. 配置AI模型优先级

基础设置

推荐配置项

Editor → Font Size：14-16px（根据屏幕大小调整）

Editor → Tab Size：2或4（根据项目规范）

AI → Model：选择OpenRouter聚合或直接使用内置模型

AI → Temperature：0.7-0.8（平衡创造力与准确性）

项目初始化

在Cursor中打开项目目录后，Cursor会自动索引项目结构。这个索引过程对于AI理解项目上下文至关重要。

# 首次打开项目后，等待索引完成 # 观察左下角状态："Indexing project..." # 索引完成后，可以通过Cmd+K调出AI对话 # Cmd+L打开Composer面板

.cursorrules文件：项目根目录放置.cursorrules文件，可以定义AI行为规范。这是Cursor区别于普通编辑器的核心特性。

03 · 核心功能

四大核心能力

1. Tab智能补全

Cursor的Tab不是传统意义的代码补全，而是基于项目上下文的多token预测。能补全函数、代码块、甚至完整的文件结构。

快捷键：Tab（接受补全） · Cmd+→（接受下一个词）

适用场景

重复性代码模式：数据库CRUD操作、React组件模板、Express路由定义

上下文相关补全：基于已有函数签名推断实现、基于变量名推断类型

自然语言转换：输入中文注释自动生成对应代码

2. Composer多文件编辑

Composer是Cursor的核心功能，可以在多个文件间协同编辑，适合重构和批量修改。

# 打开Composer：Cmd+L # 示例：重构用户认证模块 提示词： "将所有/user路由迁移到新架构， 保留中间件authenticate， 更新所有import语句， 确保向后兼容" # Composer会分析影响范围， # 列出修改文件清单， # 确认后批量执行

Composer核心特性

多文件追踪：同时处理多个文件的关联修改

变更预览：执行前预览所有变更内容

一键回滚：放弃所有变更，恢复原状

依赖分析：自动识别文件间依赖关系

快捷键：Cmd+L（打开Composer）

3. Agent模式

Agent模式让AI自主探索代码库并执行修改。适用于理解陌生代码库、大规模重构、Bug定位修复。

# Agent模式使用示例 # 1. 打开Composer (Cmd+L) # 2. 输入任务描述 # 3. 选择"Agent"模式（非Composer模式） # 4. AI自主分析、制定计划、执行修改 示例任务： "找出所有可能存在内存泄漏的代码位置， 重点关注： - 未关闭的事件监听器 - 定时器未清理 - 大对象引用" # AI会逐步探索代码库， # 列出疑似问题， # 询问是否修复

Agent vs Composer

Agent：探索性任务，理解代码后自主行动，适合陌生代码库分析

Composer：确定性任务，按指令执行修改，适合已知需求的批量编辑

推荐：先用Agent理解问题，再用Composer执行修改

4. 项目索引

Cursor会对项目建立向量索引，用于快速检索和上下文理解。索引质量直接影响AI输出质量。

  • 首次打开项目后等待索引完成
  • 大项目可以使用局部索引（只索引src目录）
  • 索引更新：Cursor会自动增量更新，无需手动操作
  • 重置索引：Settings → AI → Reset Project Index（当AI表现异常时）

    05 · MCP配置

    连接外部工具

    MCP（Model Context Protocol）允许Cursor连接外部工具和服务，扩展AI能力边界。

    常见MCP集成场景

    文件系统操作

    AI可以读取、创建、修改项目文件，无需手动操作。

    Git操作

    集成Git命令，AI可以查看diff、提交代码、处理冲突。

    终端执行

    AI可以运行命令行工具，执行构建、测试、部署。

    数据库连接

    直连数据库，执行查询、数据操作。

    外部API调用

    连接第三方服务，扩展AI能力（如搜索、翻译等）。

    MCP配置方法

    # 1. 打开Cursor设置 # Settings → MCP Server # 2. 添加MCP配置文件 # 路径：~/.cursor/mcp.json # 3. 配置示例 { "mcpServers": { "filesystem": { "command": "npx", "args": ["-y", "@modelcontextprotocol/server-filesystem", "/Users/opc/projects"] }, "git": { "command": "npx", "args": ["-y", "@modelcontextprotocol/server-git"] } } }

    注意：MCP配置涉及安全考量。确保只授权可信的工具访问。

    06 · Skills定制

    .cursorrules配置文件

    .cursorrules是Cursor的核心特性，允许为特定项目定义AI行为规范。这对于OPC保持代码一致性至关重要。

    为什么需要.cursorrules

    代码风格统一

    统一命名规范、缩进风格、注释格式，避免AI生成代码风格不一致。

    技术栈约束

    明确项目使用的框架版本、依赖库、目录结构，AI不会引入不兼容的技术。

    业务规则固化

    沉淀业务逻辑、验证规则、错误处理方式，AI生成代码符合业务预期。

    团队知识传递

    即使是一个人公司，时间久了也会遗忘项目细节，.cursorrules是"第二记忆"。

    创建.cursorrules

    # 在项目根目录创建 .cursorrules 文件 # 文件结构示例 # ==================== # 项目概述 本项目是OPC节点百科后端API，使用Node.js + Express构建。 采用RESTful架构，数据存储使用JSON文件。 # 技术栈 - Runtime: Node.js 18+ - Framework: Express 4.x - 包管理: pnpm - 代码规范: ESLint + Prettier # 代码风格 - 缩进：2空格 - 变量命名：camelCase（变量）、PascalCase（组件/类） - 常量命名：UPPER_SNAKE_CASE - 注释语言：中文优先 # API设计规范 - 路由前缀：/api/ - 响应格式：{ success: boolean, data: any, error: string|null } - 状态码：200成功，400客户端错误，500服务器错误 # 安全规范 - 禁止在代码中硬编码密钥 - 所有敏感配置从环境变量读取 - 用户输入必须验证和清理 # 错误处理 - 同步代码使用try-catch - 异步代码使用Promise.catch - 统一错误响应格式

    进阶用法：多语言支持

    # .cursorrules支持在特定代码区域定义规则 # 例如在TypeScript文件中 /* @崖Cursor:typescript - 严格模式开启 - 接口命名：I开头（IUserData） - 类型推断优先于类型声明 */ # 在React组件中 /* @崖Cursor:react - 使用函数组件而非类组件 - Hooks规范遵循React官方指南 - CSS使用Tailwind原子化类 */

    最佳实践：每个项目都应该有.cursorrules文件。OPC应该在项目初始化时创建此文件，定义技术栈、代码规范、业务规则。

    07 · 实战案例

    典型OPC工作流

    案例1：中文Prompt开发

    场景

    需要创建一个用户注册API，包括参数验证、密码加密、数据库存储。

    # 在Composer中输入中文Prompt "创建用户注册接口 POST /api/users/register 需求： 1. 接收email、password、nickname三个字段 2. email格式验证（正则） 3. password至少8位，包含大小写字母和数字 4. password使用bcrypt加密（salt rounds: 10） 5. email查重，冲突返回409状态码 6. 成功后返回用户信息（不含password） 使用CommonJS模块规范， 响应格式统一使用 { success, data, error }， 参考项目中已有的 /api/auth/login 实现风格" # Cursor会： # 1. 分析项目结构 # 2. 识别已有的auth/login实现 # 3. 生成符合项目规范的代码 # 4. 预览修改的文件和内容

    案例2：Bug修复

    场景

    用户反映支付回调接口偶发性失败，需要定位并修复问题。

    # 1. 打开Composer，输入Bug描述 "分析并修复支付回调接口 /api/payment/callback 问题描述： - 偶发性返回500错误 - 错误日志：[ERR] JSON parse error - 发生频率：约5%的请求 可能原因： - 第三方支付平台回调数据格式不一致 - 某些情况下回调数据为空或异常 任务： 1. 添加详细日志记录回调原始数据 2. 增加数据验证和异常处理 3. 避免JSON parse失败导致服务崩溃 4. 确保任何情况下都返回200给支付平台" # 2. Cursor分析代码，定位问题 # 3. 生成修复方案 # 4. 确认后应用修改

    案例3：代码重构

    场景

    随着功能增加，现有代码结构混乱，需要重构以提升可维护性。

    # 1. 使用Agent模式理解代码现状 "分析当前项目架构： 1. 统计各模块代码行数和复杂度 2. 识别违反设计模式的代码（过长的函数、重复代码） 3. 评估模块间耦合度 4. 提出重构优先级建议 报告格式： - 问题模块列表 - 具体重构建议 - 预计影响范围" # 2. 根据Agent分析，制定重构计划 # 3. 使用Composer执行重构 "重构数据访问层： 1. 将 /data 目录下的直接文件操作改为Repository模式 2. 创建统一的DataStore类 3. 抽象CRUD方法：findAll, findById, create, update, delete 4. 保持现有API兼容性，不改变对外接口 5. 更新所有调用方代码" # 4. 执行完成后运行测试验证

    08 · 常见问题

    FAQ

    Cursor和VS Code是什么关系？
    Cursor基于VS Code fork，继承了VS Code的核心功能和插件生态。最大的区别是Cursor深度集成了AI能力，而VS Code需要额外安装Copilot等插件。
    Cursor的AI模型是如何工作的？
    Cursor通过API调用第三方AI模型（OpenAI、Anthropic等），自己不做模型训练。输入的代码会发送到模型服务商，模型返回补全建议或编辑内容。
    我的代码会不会被用于训练？
    Cursor官方声明不会将用户代码用于模型训练。但建议查看隐私政策了解详情。对于高度敏感的代码，可以考虑自托管方案或使用本地模型。
    Cursor卡顿或响应慢怎么办？
    1. 检查网络连接 2. 切换到更快的模型 3. 重置项目索引（Settings → AI → Reset Index）4. 检查是否有大规模文件扫描任务正在运行
    如何取消Pro自动续费？
    Account Settings → Plans → Cancel Subscription。注意取消后当前付费周期内仍可使用，下个周期不再扣费。
    能否在Cursor中使用自己的API Key？
    可以。在Settings → AI → Model中，选择"Use my own key"，然后输入OpenAI或Anthropic的API Key。这样可以使用自己的账号额度。
    .cursorrules文件会被AI忽略吗？
    正常情况下不会，.cursorrules是Cursor官方支持的功能。但AI可能不会100%遵守所有规则，建议保持规则简洁明确，避免过于细节的要求。
    Cursor支持哪些编程语言？
    理论支持所有主流编程语言，包括但不限于：JavaScript/TypeScript、Python、Go、Rust、Java、C++、C#、PHP、Ruby、Swift、Kotlin等。
    团队多人使用Cursor如何保持一致性？
    Business版本提供团队管理功能，可以统一配置AI规则。对于Pro及以下版本，建议在代码仓库中维护.cursorrules文件，团队成员clone后自动应用。

    Cursor学习路径

    • 第一天：安装Cursor，配置基础设置，体验Tab补全
    • 第二天：使用Composer完成一次功能开发（中文Prompt）
    • 第三天：创建项目.cursorrules，定义代码规范
    • 第四天：尝试Agent模式解决一个问题
    • 第五天：整合工作流，Cursor处理日常开发 + Claude Code处理复杂任务

    记住：工具是为效率服务的，不要为了学习而学习。找到最适合自己的工作方式，持续优化。
