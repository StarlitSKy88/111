Docker

容器化技术的核心工具。让你的应用在任何环境下一致运行，从开发机到生产服务器无缝迁移。OPC不可或缺的运维利器。

最后修订：2026年5月14日 · 容器化工具
核心定位

为什么OPC用Docker？

Docker是一个容器化平台。它的核心理念是：将应用及其所有依赖打包成一个标准化的单元，这个单元可以在任何Docker环境中一致运行。"在我机器上能跑"的问题，从此消失。

维度有Docker无Docker
环境一致性开发、测试、生产完全一致环境差异导致各种奇怪问题
部署速度秒级启动完整环境手动安装配置，耗时数小时
资源占用共享系统内核，轻量高效每个虚拟机独占完整系统
迁移难度一次构建，随处运行重新搭建环境费时费力
协作效率一个镜像全员一致每人环境不同，问题难复现
生产运维容器编排，弹性伸缩手动管理服务器

Docker解决的三个核心问题

1 环境不一致

「在我机器上能跑」是开发中最烦人的问题。Docker确保开发、测试、生产环境完全一致，再也没有"为什么线上挂了"的困惑。

2 依赖地狱

Node版本、Python版本、各种系统库……安装一次环境要折腾半天。Docker把所有依赖打包，拿到镜像直接跑。

3 部署复杂

换服务器要从零搭建环境。Docker让你在服务器上拉取镜像，一行命令启动完整应用，省去大量手工操作。

Docker = 应用的精装集装箱。无论货物（应用）要运到哪个港口（服务器），集装箱本身不变，运输方式不变。

核心概念

理解三个关键术语

镜像

Image - 应用的模板

镜像是一个只读的模板，包含了运行应用所需的所有内容：代码、运行时、环境变量、配置文件。你可以把镜像理解为一个菜谱，它告诉你需要什么原料、如何制作。

容器

Container - 镜像的运行实例

容器是镜像的运行实例。你可以基于同一个镜像创建多个容器，每个容器都是独立的、相互隔离的。就像根据同一个菜谱可以做出多份菜。

Dockerfile

Dockerfile - 构建镜像的配方

Dockerfile是一个文本文件，包含了一系列指令，用于构建Docker镜像。它定义了基础系统、安装依赖、复制代码、配置环境等所有步骤。

三者的关系

# 1. 编写 Dockerfile（配方） # 2. docker build 构建出 Image（成品） # 3. docker run 基于 Image 创建 Container（正在运行的产品） Dockerfile → docker build → Image → docker run → Container

镜像的层级结构

Docker镜像采用分层存储，每一层只记录与上一层的差异。这种设计让镜像可以共享底层文件，大幅节省存储空间和传输带宽。

# 一个Node.js应用的镜像可能包含以下层级： # - 底层：操作系统的精简版本（Alpine Linux） # - 第二层：Node.js运行时环境 # - 第三层：npm包管理工具 # - 第四层：项目依赖（node_modules） # - 第五层：应用源代码
快速上手

安装Docker Desktop

操作系统下载地址系统要求
macOSdocker.com/products/docker-desktopApple Silicon 或 Intel芯片，macOS 11+
Windowsdocker.com/products/docker-desktopWSL2 或 Hyper-V，Windows 10/11
Linuxdocker.com/engine/installUbuntu, Debian, Fedora, CentOS等

macOS安装步骤

  1. 下载 Docker Desktop for Mac（选择Apple Silicon或Intel版本）
  2. 双击 .dmg 文件，将Docker图标拖入Applications文件夹
  3. 首次启动需要输入管理员密码（用于创建虚拟化环境）
  4. 等待Docker服务启动，状态栏显示鲸鱼图标表示就绪

验证安装

# 打开终端，运行以下命令检查Docker是否正常 docker --version docker ps docker info

如果看到Docker版本信息和容器列表，说明安装成功。如果提示权限错误，可能需要把当前用户加入docker用户组：

# Linux/macOS 添加用户组（不需要可以跳过） sudo usermod -aG docker $USER # 然后重新登录终端

OPC提示：Docker Desktop首次启动会占用约1GB内存用于创建Linux虚拟机。这是正常的，不是内存泄漏。如果资源紧张，可以限制Docker的资源使用：Preferences → Resources → Memory调低到2GB。

核心命令

最常用的Docker CLI

镜像操作

# 构建镜像 # -t 指定镜像名:标签，. 表示当前目录的Dockerfile docker build -t my-app:1.0 . # 查看本地镜像列表 docker images # 删除镜像 docker rmi my-app:1.0 # 拉取远程镜像 docker pull node:18-alpine # 推送镜像到仓库 docker push my-username/my-app:1.0

容器操作

# 创建并启动容器 # -d 后台运行，-p 端口映射（主机:容器），--name 指定容器名 docker run -d -p 3000:3000 --name my-app-container my-app:1.0 # 查看运行中的容器 docker ps # 查看所有容器（包括已停止的） docker ps -a # 停止容器 docker stop my-app-container # 启动已停止的容器 docker start my-app-container # 删除容器（必须先停止） docker rm my-app-container # 进入容器内部执行命令 docker exec -it my-app-container /bin/sh

日志和调试

# 查看容器日志（-f 实时跟踪） docker logs -f my-app-container # 查看最近100行日志 docker logs --tail 100 my-app-container # 查看容器详细信息 docker inspect my-app-container # 查看容器资源使用 docker stats

一键清理

# 删除所有已停止的容器 docker container prune # 删除所有未使用的镜像 docker image prune -a # 删除所有停止的容器、未使用的网络、 dangling 镜像 docker system prune # 完全清理（包含 Volumes） docker system prune --volumes

docker ps

查看当前运行的容器，相当于"任务管理器"。快速了解有哪些容器在跑。

docker logs

查看容器输出日志。应用出错时首先查看这里，相当于看"控制台输出"。

docker exec

进入运行中的容器内部。用于调试、查看文件、修改配置。

docker build

根据Dockerfile构建镜像。每次代码更新后需要重新构建才能生效。

Docker Compose

编排多容器应用

Docker Compose是一个用于定义和运行多容器应用的工具。通过一个YAML文件，你可以描述多个服务（数据库、缓存、后端、前端）以及它们之间的关系，然后一键启动全部。

docker-compose.yml 示例

这是一个典型的Web应用架构：Nginx反向代理 + Node.js后端 + PostgreSQL数据库

version: '3.8' services: # 前端Nginx服务 nginx: image: nginx:alpine ports: - "80:80" volumes: - ./nginx.conf:/etc/nginx/nginx.conf:ro depends_on: - backend networks: - app-network # 后端Node.js服务 backend: build: context: ./backend dockerfile: Dockerfile environment: - NODE_ENV=production - DATABASE_URL=postgres://user:pass@db:5432/mydb depends_on: - db networks: - app-network # PostgreSQL数据库 db: image: postgres:15-alpine environment: - POSTGRES_USER=user - POSTGRES_PASSWORD=pass - POSTGRES_DB=mydb volumes: - postgres-data:/var/lib/postgresql/data networks: - app-network # Redis缓存 redis: image: redis:7-alpine networks: - app-network networks: app-network: driver: bridge volumes: postgres-data:

常用Compose命令

# 启动所有服务（-d 后台运行） docker-compose up -d # 停止所有服务 docker-compose down # 查看服务状态 docker-compose ps # 查看服务日志 docker-compose logs -f backend # 重新构建并启动 docker-compose up -d --build # 进入后端容器 docker-compose exec backend /bin/sh # 扩展服务（启动多个实例） docker-compose up -d --scale backend=3

OPC的典型使用场景

开发环境

一键启动完整开发环境：数据库、Redis、后端API、前端。不需要手动安装各种服务。

测试环境

每次测试前从干净状态开始，确保测试结果可重复。不受本地环境影响。

部署验证

在本地模拟生产环境架构，验证Docker Compose配置是否正确，再发布到服务器。

实战案例

容器化一个Node.js应用

第一步：创建项目结构

my-node-app/ ├── src/ │ └── index.js ├── Dockerfile ├── .dockerignore ├── package.json └── docker-compose.yml

第二步：编写Dockerfile

# 选择轻量级基础镜像 FROM node:18-alpine # 设置工作目录 WORKDIR /app # 复制依赖文件（先复制package.json可以利用Docker缓存） COPY package*.json ./ # 安装依赖 RUN npm ci --only=production # 复制源代码 COPY src/ ./src/ # 暴露端口 EXPOSE 3000 # 启动命令 CMD ["node", "src/index.js"]

第三步：创建.dockerignore

和.gitignore类似，.dockerignore告诉Docker哪些文件不要打包进镜像，可以大幅减小镜像体积。

# 不需要打包的文件 node_modules npm-debug.log .git .gitignore README.md .env* *.md dist coverage .vscode .idea

第四步：创建docker-compose.yml（可选，用于本地开发）

version: '3.8' services: app: build: . ports: - "3000:3000" volumes: - ./src:/app/src # 源代码挂载，改动无需重新构建 environment: - NODE_ENV=development - PORT=3000 command: node src/index.js

第五步：构建和运行

# 构建镜像 docker build -t my-node-app:1.0 . # 运行容器 docker run -d -p 3000:3000 --name my-node-app my-node-app:1.0 # 查看运行状态 docker ps # 查看日志 docker logs -f my-node-app

开发模式下的热重载

如果使用docker-compose开发，通过volumes挂载源代码目录，代码修改后容器内会自动看到变化，不需要每次重新构建。

# 但Node.js默认不会热重载，需要使用 nodemon 等工具 # 修改package.json的启动命令： # "dev": "nodemon src/index.js" # 修改Dockerfile： CMD ["npm", "run", "dev"]

OPC提示：如果数据库也在Docker中运行，记得在连接字符串中使用服务名db而不是localhost。Docker Compose创建的网络中，服务名就是主机名。

最佳实践

生产环境Dockerfile技巧

多阶段构建

多阶段构建可以大幅减小最终镜像体积。只把运行时需要的东西放进去，构建工具和源代码都不需要。

# 第一阶段：构建 FROM node:18 AS builder WORKDIR /app COPY package*.json ./ RUN npm ci COPY . . RUN npm run build # 第二阶段：运行（使用更小的基础镜像） FROM node:18-alpine AS production WORKDIR /app COPY --from=builder /app/dist ./dist COPY --from=builder /app/node_modules ./node_modules COPY package*.json ./ # 以非root用户运行（安全） USER node CMD ["node", "dist/index.js"]

利用Docker缓存加速构建

Docker按层缓存构建结果。如果某层没变化，会直接使用缓存。合理安排COPY顺序可以加速构建。

# 好的顺序：先复制依赖文件，安装依赖，再复制源代码 # 这样修改代码后，依赖安装层会被缓存 COPY package*.json ./ RUN npm ci COPY src/ ./src/

减小镜像体积的技巧

  • 使用 alpine 标签的镜像，比完整版小很多（node:18-alpine 只有约170MB）
  • 使用多阶段构建，只把运行时内容放入最终镜像
  • 在.dockerignore中排除不需要的文件
  • 合并多个RUN指令减少层数
  • 不要把构建工具装进生产镜像

安全最佳实践

# 1. 使用非root用户运行容器 USER node # 2. 不要在镜像中存储敏感信息，使用环境变量或Docker secrets # 错误： # RUN npm config set token xxx # 正确： ENV NPM_TOKEN=xxx # 3. 定期更新基础镜像（不要用 latest 标签） FROM node:18.20.0-alpine3.19 # 指定精确版本 # 4. 扫描镜像漏洞 docker scout cves my-app:1.0

环境变量最佳实践

# 在Dockerfile中设置默认值 ENV NODE_ENV=production ENV PORT=3000 # 运行时可以覆盖 docker run -e PORT=8080 -p 8080:8080 my-app # docker-compose中配置 environment: - NODE_ENV=production - DATABASE_URL=postgres://user:pass@db:5432/mydb - API_KEY=${API_KEY} # 从主机环境变量读取
常见问题

FAQ

Docker和虚拟机有什么区别？

虚拟机需要模拟完整硬件、安装完整操作系统，资源占用大、启动慢。Docker共享宿主机的内核，容器是轻量级的进程隔离，启动只需几秒。一台机器可以运行几十个Docker容器，但运行不了几个完整的虚拟机。

macOS和Windows上Docker是怎么工作的？

macOS和Windows本身不支持直接运行Linux容器，所以Docker Desktop会创建一个Linux虚拟机来运行Docker。在macOS上是通过HyperKit，在Windows上是通过WSL2或Hyper-V。这个虚拟机对用户是透明的，你感觉就像在Linux上运行Docker一样。

Docker占用多少系统资源？

Docker Desktop默认限制为2GB内存，可以在设置中调整。实际容器运行的资源占用取决于你的应用，空闲状态下几乎不占用资源。建议开发机器至少16GB内存，这样同时跑几个容器也不会卡。

容器内数据如何持久化？

容器的文件系统是临时的，删除容器后数据会丢失。如果需要持久化数据，使用Docker Volumes把宿主机的目录挂载到容器内，或者使用数据库容器并配置数据卷。docker-compose中的volumes配置就是用于数据持久化的。

如何查看Docker镜像的大小？

运行docker images可以看到镜像大小。使用多阶段构建和使用alpine基础镜像可以显著减小体积。对于Node.js应用，最终镜像控制在200MB以内是合理的。

容器内无法访问网络怎么办？

首先检查容器是否在运行：docker ps。然后检查网络连通性：docker exec -it container-name ping google.com。如果网络不通，可能是DNS配置问题，在docker-compose.yml中添加dns: 8.8.8.8尝试解决。

如何在不同电脑间同步开发环境？

只需要同步Dockerfile和docker-compose.yml，团队成员拉取代码后运行docker-compose up就能得到完全一致的环境。不需要手动安装任何依赖，所有东西都打包在镜像里。

Docker在生产环境怎么用？

小型项目可以用Docker Compose直接在服务器上运行。docker-compose up -d启动，docker-compose logs -f查看日志，docker-compose down/up更新。对于需要高可用和弹性伸缩的生产环境，建议使用Kubernetes（K8s）来编排容器。

容器内的端口怎么对外访问？

使用-p参数映射端口：-p 8080:3000表示宿主机的8080端口映射到容器的3000端口。docker-compose.yml中的ports配置同理：ports: - "8080:3000"。确保防火墙允许访问宿主机的对应端口。

Docker使用总结

  • Docker解决环境不一致问题，一次构建到处运行
  • 理解三个核心概念：镜像、容器、Dockerfile
  • docker build/run/ps/logs是日常高频命令
  • Docker Compose编排多容器应用
  • 使用.dockerignore和 alpine 基础镜像减小体积
  • 多阶段构建是生产环境的最佳实践

OPC的核心原则是：让工具自动化，而不是人工重复劳动。Docker正是这个原则的体现——环境的搭建和迁移全部自动化。
