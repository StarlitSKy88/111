一、核心定位

Cloudflare是什么

Cloudflare是一家美国网络安全公司，提供网站性能优化和安全防护服务。它的核心价值在于：将你的网站流量引入全球分布的边缘节点网络，实现就近访问加速，同时过滤恶意流量。

二、快速入门

注册与接入

第一步：注册账号

  • 访问 dash.cloudflare.com
  • 使用邮箱注册（建议使用Gmail或企业邮箱）
  • 完成邮箱验证

第二步：添加域名

# 在Cloudflare Dashboard点击 "Add a Site" # 输入你的域名，如 example.com # 选择套餐：Free（免费）即可 # Cloudflare会自动扫描现有DNS记录

第三步：修改Nameservers

这是最关键的一步。域名注册商那里把DNS服务器改为Cloudflare提供的地址，这样Cloudflare才能接管你的流量。

常见注册商修改位置

Namesilo：Domain Management → Nameservers → Enter My Own Nameservers

GoDaddy：Domain Settings → Nameservers → Change → Enter custom

阿里云（万网）：域名控制台 → 域名详情 → DNS修改

腾讯云：域名服务 → 域名管理 → DNS服务器

# Cloudflare会提供两个Nameservers，如： jim.ns.cloudflare.com elma.ns.cloudflare.com # 在你的域名注册商处，将域名注册商的默认NS替换为以上两个 # 修改后通常需要 24-48小时 生效（全球DNS传播） # 验证方法：在 Cloudflare Dashboard 查看域名状态 # Status: Active 表示接入成功

Nameservers修改冷知识：修改NS记录后不要急着删除旧的域名解析服务，原解析商的账号保留一段时间。Cloudflare只接管DNS查询流量，域名续费、备案等工作仍在原注册商处进行。

三、DNS管理

DNS记录配置

DNS（Domain Name System）是将域名指向服务器IP的服务。在Cloudflare Dashboard的DNS面板中管理。

常见记录类型

记录类型用途填写方式
A将域名指向IPv4服务器IPName: @ / IPv4: 你的服务器IP
AAAA将域名指向IPv6服务器IPName: @ / IPv6: 你的服务器IPv6
CNAME域名别名，如www指向主域名Name: www / Target: example.com
MX邮件服务器配置Name: @ / Mail server: mail.example.com / Priority: 10
TXT验证记录（如SPF、DKIM）Name: @ / Content: v=spf1 include:_spf.example.com ~all

Proxied vs DNS-only

Cloudflare的DNS记录有两种状态，这是最重要的概念：

状态橙色云朵（Proxied）灰色云朵（DNS-only）
流量经过Cloudflare边缘节点直接到达源服务器
CDN加速✓×
DDoS防护✓×
隐藏真实IP✓×
SSL证书✓×
适用场景网站、API、Web应用邮件服务器、SSH、游戏服务器

OPC建议：网站类的A记录和CNAME记录，务必使用橙色Proxied状态（CDN加速+隐藏真实IP）。只有邮件服务器、SSH、游戏端口等无法通过Cloudflare代理的才使用灰色DNS-only。

注意：隐藏真实IP

使用Proxied状态后，你的服务器真实IP会被Cloudflare隐藏，访问者只能看到Cloudflare的边缘节点IP。这能有效防止直接对源服务器IP的攻击。但注意：一旦服务器IP泄露（比如通过DNS查询工具），攻击者可以直接绕过Cloudflare。

四、CDN加速

缓存与性能优化

Cloudflare的核心能力之一是CDN（Content Delivery Network）。用户访问你的网站时，请求会被引导到最近的边缘节点，静态资源直接从边缘节点返回，大幅降低延迟。

Caching（缓存）

缓存级别

Cloudflare提供三个缓存级别（在Dashboard → Caching → Configuration设置）：

Basic：仅缓存静态资源（HTML/CSS/JS/图片）

Simplified：缓存所有符合规则的资产

Aggressive：更积极缓存，包括带查询参数的请求

缓存时长

在同一个配置页面可以设置Edge Cache TTL（边缘节点缓存时间）和Browser Cache TTL（浏览器缓存时间）。

建议：静态资源设置较长缓存（1个月），动态内容设置较短或不缓存。

Auto Minify（自动压缩）

Cloudflare可以自动压缩JS、CSS、HTML文件，移除空格和注释，通常能减少20-30%文件体积。

# 在 Dashboard → Speed → Optimization 设置 # 自动压缩选项： # - JavaScript 压缩 # - CSS 压缩 # - HTML 压缩 # 建议全部开启，对国内访问速度有改善

Rocket Loader（即时加载）

Rocket Loader会异步加载JavaScript文件，让页面更快渲染。但可能影响依赖脚本执行顺序的代码。

开启建议

建议先在Cloudflare的Speed设置中开启Auto Minify（对所有网站安全）。Rocket Loader谨慎开启，如果网站有依赖严格加载顺序的JS脚本（如某些第三方SDK），需要先测试。

Brotli压缩

Cloudflare支持Brotli压缩（比Gzip更高效的压缩算法），默认开启。无需手动配置。

Speed测试建议

  • 使用 Lighthouse 或 GTmetrix 测试加速前后性能
  • 开启Auto Minify（JS/CSS/HTML全部）
  • 保持Rocket Loader关闭，除非你确定脚本加载顺序不影响业务
  • 静态资源通过Page Rules设置更长的缓存时间

    加密模式选择

    Cloudflare为每个接入的域名提供免费的边缘SSL证书。但证书模式的选择决定了端到端加密的安全程度。

    四种SSL模式

    模式浏览器→CloudflareCloudflare→源服务器安全等级
    FlexibleHTTPSHTTP（明文）低
    FullHTTPSHTTPS（自签证书也可）中
    Full (strict)HTTPSHTTPS（有效证书）高
    Strict (strict)HTTPS + 证书验证HTTPS（有效证书）最高

    OPC建议：如果你的源服务器已有有效SSL证书，选 Full (strict)。如果服务器没有证书但需要加密，选 Flexible（临时方案）。强烈建议配置源服务器的有效SSL证书，然后使用Full (strict)模式。

    边缘证书 vs 源证书

    理解SSL在Cloudflare架构中的工作方式很重要：

    架构 SSL流程

    1. 边缘证书（Edge Certificate）：Cloudflare自动颁发，管理浏览器到Cloudflare之间的加密。由Cloudflare根证书签发，免费。

    2. 源服务器证书（Origin Certificate）：安装在你的源服务器上，管理Cloudflare到源服务器之间的加密。可以是Cloudflare Origin CA（免费）或 Let's Encrypt（免费）。

    源证书申请（Cloudflare Origin CA）

    # 在 Cloudflare Dashboard → SSL/TLS → Origin Server # 点击 "Create Certificate" # 选择 "Generate a certificate signed by Cloudflare" # 添加主机名：*.example.com 和 example.com # 有效期：15年 # 下载证书文件（.pem 或 .crt） # 将证书上传到服务器 scp origin.pem root@你的服务器:/etc/ssl/certs/origin.pem scp origin.key root@你的服务器:/etc/ssl/private/origin.key # Nginx配置示例 ssl_certificate /etc/ssl/certs/origin.pem; ssl_certificate_key /etc/ssl/private/origin.key;

    HTTPS强制跳转

    如果你希望所有HTTP访问都自动跳转到HTTPS，在Cloudflare Dashboard中开启"Always Use HTTPS"即可，无需修改服务器配置。

    六、DDoS防护

    自动防护机制

    Cloudflare的DDoS防护是自动且免费的。这不需要你做任何配置，只要域名接入Cloudflare，防护就自动生效。

    防护层级

    L3/L4 DDoS防护 免费

    网络层和传输层DDoS防护。自动检测并缓解大容量攻击（如UDP Flood、SYN Flood）。无需配置。

    L7 DDoS防护 免费

    应用层防护。检测HTTP/HTTPS层面的攻击（如CC攻击、HTTP Flood）。免费版提供基础防护。

    Advanced DDoS Protection 付费

    更高级的L7防护，付费版功能。提供更细致的流量分析和自定义规则。

    Under Attack Mode

    当检测到正在遭受攻击时，可以在Cloudflare Dashboard开启Under Attack Mode。此时访问你的网站会显示Cloudflare的挑战页面（JS验证），过滤掉恶意流量。

    # 在 Dashboard → Overview → Under Attack Mode # 点击 "Turn On" 开启 # 正常情况下保持关闭，只有被攻击时才开启 # Under Attack Mode会让所有访问者通过JS挑战，可能影响用户体验

    IP访问规则

    你可以手动屏蔽特定IP或国家/地区的访问：

    # 在 Dashboard → Security → WAF → IP Access Rules # 可以设置： # - 屏蔽特定IP或IP段 # - 屏蔽整个国家/地区 # - 允许特定IP或IP段（白名单） # - 设置访问挑战（验证码）而非直接拒绝

    OPC注意：DDoS防护不收费是Cloudflare最大的价值之一。传统方案需要购买高防IP（¥2000/月起），而Cloudflare免费版已经能应对中小规模的DDoS攻击。

    七、Page Rules

    自定义规则

    Page Rules允许你对特定URL模式设置自定义行为：缓存策略、重定向、HTTPS强制、HSTS配置等。免费版可以使用3条Page Rules。

    常见规则场景

    规则模式行为
    静态资源缓存example.com/static/*Cache Level: Cache everything, Edge TTL: 1 month
    强制HTTPSexample.com/*Always Use HTTPS
    301重定向example.com/old-page/*Forwarding: 301 to https://example.com/new-page/$1
    绕过缓存（登录用户）example.com/dashboard/*Cache Level: Bypass
    添加安全头example.com/api/*Security Headers: Strict-Transport-Security

    规则示例：静态资源长期缓存

    # URL Pattern: example.com/assets/* # Settings: Cache Level = Cache everything Edge Cache TTL = 1 month Browser Cache TTL = 1 month Origin Cache Control = On # 效果：/assets/* 路径下的所有文件缓存1个月

    规则示例：全站强制HTTPS

    # URL Pattern: example.com/* # Settings: Always Use HTTPS = On Automatic HTTPS Rewrites = On # 效果：所有HTTP请求自动301跳转到HTTPS

    规则优先级

    Page Rules按优先级顺序匹配（从上到下，最上面的优先级最高）。你可以拖动调整顺序。

    免费版限制

    免费版最多3条Page Rules。付费版有更多规则配额。如果规则不够用，可以考虑使用Workers实现更灵活的逻辑。

    八、Workers

    边缘Serverless函数

    Cloudflare Workers是在Cloudflare边缘节点运行的JavaScript（/ Rust）代码。可以拦截请求、修改响应、生成动态内容，甚至搭建完整的API。

    免费额度

    免费套餐 免费

    每天10万次请求

    CPU时间：每次请求最多50ms

    内存：128MB/请求

    足够支撑一个月的小型项目

    付费套餐（$5/月）

    每天1000万次请求

    每次请求CPU时间提高到30秒

    支持Cron Triggers（定时任务）

    快速开始

    # 安装 Wrangler CLI npm install -g wrangler # 创建新项目 wrangler generate my-worker cd my-worker # 编辑 src/index.js addEventListener('fetch', event => { event.respondWith(handleRequest(event.request)) }) async function handleRequest(request) { return new Response('Hello World!', { headers: { 'Content-Type': 'text/plain' } }) } # 部署 wrangler deploy

    实用场景

    请求拦截与改写

    修改请求头、URL参数重写、A/B测试流量分发。

    静态网站认证

    为静态网站添加简单的密码保护、IP白名单、JWT验证。

    API代理

    代理第三方API，添加缓存、速率限制、响应转换。

    实时重定向

    基于地理位置、国家、设备的动态重定向。

    部署到自定义域名

    # 绑定自定义域名 wrangler route add "https://api.example.com/*" --script-name my-worker # 或在 Dashboard → Workers → Manage Domains 添加

    Workers vs 传统服务器：Workers是无状态的，每次请求独立处理。不适合需要持久连接、会话管理、文件读写的场景。但对于API代理、请求改写、认证拦截等场景，Workers比传统服务器更简单、更便宜（免费额度够用）。

    九、常见问题

    FAQ

    Q: Cloudflare国内访问速度如何？

    A: 国内访问Cloudflare托管的网站会比较慢，因为流量需要绕道海外。如果你的主要用户在国内，建议：1）使用国内云服务商（阿里云/腾讯云）作为主域名解析；2）将海外子域名通过Cloudflare解析加速。也可以在Cloudflare的Speed设置中开启大陆优化（$200/月起，需企业版）。

    Q: Cloudflare会不会导致网站打不开？

    A: 极少数情况下，Cloudflare的防护机制可能误判正常用户为机器人，弹出验证页面。如果遇到，可以在Dashboard暂时关闭Security选项排查。同时确保没有开启Under Attack Mode。

    Q: 使用Cloudflare还需要源服务器SSL证书吗？

    A: 从浏览器到Cloudflare之间的加密由边缘证书保障（自动颁发）。但Cloudflare到源服务器之间，建议配置源证书（Cloudflare Origin CA免费），否则这段是明文传输。如果不配置，至少选择Flexible SSL模式。

    Q: Cloudflare的免费版可以用在商业网站吗？

    A: 可以。Cloudflare免费版对商业使用没有限制（个人项目、商业网站均可）。唯一需要注意的是，如果你的网站有超大规模流量（>10Gbps攻击），免费防护可能不够，此时需要付费方案。

    Q: 域名迁移到Cloudflare会影响现有解析吗？

    A: 迁移本身不影响DNS解析记录（这些记录可以在迁移前导入Cloudflare）。但需要修改注册商的NS记录为Cloudflare提供的地址，这会带来短暂的DNS切换时间（通常几小时）。建议在低峰期操作。

    Q: Cloudflare Workers和传统Serverless（如AWS Lambda）有什么区别？

    A: 主要区别：1）Workers运行在边缘节点，延迟更低；2）Workers免费额度更大（10万次/天）；3）Workers只支持JS/Rust；4）AWS Lambda支持更多语言和更复杂的运行时。OPC阶段Workers免费额度足够，后期可根据需求迁移。

    Q: 如何彻底关闭Cloudflare？

    A: 在域名注册商处将NS记录改回原注册商的DNS服务器，然后在Cloudflare Dashboard的域名设置中点击"Remove Site"。注意：移除域名后Cloudflare不再提供任何防护。

    Q: Cloudflare被墙了怎么办？

    A: 如果你的网站使用Cloudflare且域名在大陆访问异常，通常是因为：1）网站内容触发了GFW过滤；2）域名NS记录被干扰。建议准备国内备站（使用阿里云/腾讯云），在紧急情况下切回国内解析。

    快速开始 Checklist

    • 注册Cloudflare账号（dash.cloudflare.com）
    • 添加域名，选择Free套餐
    • 在域名注册商处修改NS记录为Cloudflare提供的地址
    • 等待DNS传播（24-48小时），确认状态变为Active
    • 配置DNS记录（橙色Proxied状态）
    • 设置SSL模式为Full (strict)，申请源证书
    • 开启Auto Minify（JS/CSS/HTML全部）
    • 根据需要配置Page Rules
    • 有复杂需求时，学习使用Workers

    记住：Cloudflare是OPC最重要的基础设施工具之一。免费提供CDN、DNS、SSL、DDoS防护四合一，远超任何传统方案的性价比。学会用好它的免费功能，能为你的项目省下大量成本。
