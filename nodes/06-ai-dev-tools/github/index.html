GitHub 教程

全球最大代码托管平台。覆盖代码版本控制、GitHub Actions CI/CD、GitHub Pages 静态网站部署，让OPC拥有专业开发团队级别的代码管理能力。

本教程适合零基础OPC，假设你已有基础的计算机操作能力
一、核心定位

GitHub 对 OPC 的价值

GitHub 是全球最大的代码托管平台，也是现代软件开发的"中央神经系统"。对于OPC而言，GitHub 不仅仅是代码存储空间，而是整个开发流程的基础设施。

代码托管

代码的"云硬盘"，支持 Git 版本控制

所有代码集中存储在任何地方都能访问，支持完整的版本历史记录。即使本地电脑损坏，也能从GitHub恢复所有代码。

协作平台

代码审查、问题追踪、项目管理

Pull Request 让代码审查流程清晰，Issues 追踪功能/问题，Projects 管理任务看板。OPC一个人也能享受团队协作的效率。

CI/CD 自动化

GitHub Actions 实现自动化构建与部署

代码提交自动触发测试、构建、部署。无需手动操作，每次推送都经过自动化流水线验证。

免费静态部署

GitHub Pages 提供免费静态网站托管

前端项目直接部署到GitHub服务器，提供 custom domain 支持。无需购买服务器即可拥有可访问的网站。

OPC 使用 GitHub 的核心场景：

1. 存储所有项目代码（私有仓库免费）

2. 管理开发任务和Bug追踪

3. 自动化测试和部署流程

4. 部署静态网站（文档、落地页、MVP）

5. 展示开源项目（建立技术影响力）

二、快速上手

三分钟创建第一个仓库

GitHub 的核心概念是"仓库（Repository）"，你可以在上面存储任何项目代码。跟随下面的步骤，三分钟内创建你的第一个GitHub仓库。

第一步：创建账户

访问 github.com，点击右上角的 Sign up。填写邮箱、密码、用户名（建议用简洁的英文名）。

注意：GitHub 对大陆用户访问不稳定，需要配置网络代理（Clash）才能正常访问。建议使用英文界面，很多专业术语在中文翻译下难以理解。

第二步：创建仓库

登录后点击右上角的 + 号，选择 "New repository"。填写仓库信息：

仓库名称：my-first-project 描述：My first GitHub repository 权限：Private（私有仓库，OPC建议选这个） 勾选：Add a README file 选择：.gitignore 选择 Node（会自动配置Node项目忽略文件）

第三步：克隆到本地

创建完成后，点击仓库页面的绿色的 "Code" 按钮，复制 HTTPS 地址。

# 在终端中运行（需要先安装 Git） # Windows/Mac 均需先安装 Git：https://git-scm.com/downloads git clone https://github.com/你的用户名/my-first-project.git # 进入项目目录 cd my-first-project

Git 基础三命令

Git 的核心工作流程：修改文件 → 添加到暂存区 → 提交记录。每次提交都会生成一个唯一的版本号，可以随时回溯。

# 1. 查看当前状态（你会看到所有修改的文件） git status # 2. 添加文件到暂存区（. 表示所有文件，或指定具体文件） git add . # 3. 提交修改（-m 后面是提交说明，必须填写） git commit -m "添加首页组件" # 4. 推送代码到 GitHub（首次推送需要输入用户名和Token） git push origin main

GitHub 认证方式（重要）

2021年后 GitHub 不再支持密码认证，需要使用 Personal Access Token（个人访问令牌）或 SSH Key。

# 创建 Personal Access Token： # Settings → Developer settings → Personal access tokens → Generate new token # 勾选 repo 选项，生成后复制（只显示一次） # 克隆/推送时，用户名输入你的GitHub用户名 # 密码输入 Token（不是你的GitHub密码）

OPC 记忆法："add-commit-push" = 买菜-装袋-寄出。先 git add 暂存修改，再 git commit 装袋，最后 git push 寄出。

三、核心功能

Branches、Commits、PRs、Issues

GitHub 的核心协作模型围绕这四个概念展开：分支（Branch）隔离开发，提交（Commit）记录变化，拉取请求（PR）审核代码，议题（Issue）追踪任务。

Branches（分支）

分支允许你在不影响主代码的情况下进行实验。main（主分支）是稳定代码，功能开发在 feature 分支上进行。

# 查看所有分支（当前分支前有 *） git branch # 创建新分支 git branch feature/user-auth # 切换到新分支 git checkout feature/user-auth # 或者一步完成：创建并切换 git checkout -b feature/user-auth # 合并分支（先切回 main，再合并） git checkout main git merge feature/user-auth

Commits（提交）

每次 git commit 都会生成一个唯一的 SHA 哈希值，代表一个"存档点"。你可以随时用这个哈希值回到过去的任何版本。

# 查看提交历史 git log # 简洁模式查看 git log --oneline # 回到某个提交（慎用，会丢失后续提交） git reset --hard 提交的SHA前7位 # 查看某个文件的历史 git log --follow -p 文件路径

Pull Requests（PR）

PR 是代码审查的核心。当你完成一个功能分支，想把它合并到 main 时，创建 PR。其他开发者可以审查代码、提建议、批准合并。

# 1. 推送分支到 GitHub git push origin feature/user-auth # 2. 在 GitHub 页面点击 "Compare & pull request" # 3. 填写 PR 描述（说明改了什么、为什么改） # 4. 等待审查，点击 "Merge" 合并到 main # 5. 合并后删除分支（GitHub 会提示）

OPC 的 PR 策略：

虽然OPC一个人开发，但建议把每个功能当作一个"PR"来做。这样做的好处：

1. 每次合并都有清晰的变更记录

2. 如果发现有问题，可以单独回滚某个功能

3. 培养工程思维，为未来团队协作做准备

Issues（议题）

Issues 是任务追踪系统。可以创建功能需求、Bug报告、改进建议。每个 Issue 都有唯一的编号，方便在代码中引用。

# 在 PR 描述中引用 Issue # 例如：closes #23 或 Fixes #23（会自动关闭该 Issue） # Issue 标签示例 # - bug: 功能错误 # - enhancement: 功能增强 # - documentation: 文档更新 # - good first issue: 适合新手

GitHub Actions 基础

GitHub Actions 是内置的 CI/CD 系统，可以在代码推送时自动运行测试、构建、部署。

# .github/workflows/nodejs.yml # Node.js 项目的自动化测试工作流 name: Node.js CI on: push: branches: [ main ] pull_request: branches: [ main ] jobs: build: runs-on: ubuntu-latest steps: - uses: actions/checkout@v4 - name: Use Node.js uses: actions/setup-node@v4 with: node-version: '20' - run: npm install - run: npm test
工作流文件触发条件用途
nodejs.ymlpush/PRNode.js 测试与构建
deploy.ymlpush to main自动部署到 Vercel
pages.ymlpush to gh-pages部署 GitHub Pages
四、GitHub Pages

免费静态网站托管

GitHub Pages 提供免费的静态网站托管服务，非常适合文档、博客、落地页、MVP展示。对于不想购买云服务器的OPC来说，这是零成本的上线方案。

启用 GitHub Pages

# 1. 在仓库设置中启用 GitHub Pages # Settings → Pages → Source → Deploy from a branch # 选择 main 分支和 / (root) 目录 # 2. 几分钟后你的网站就可以访问了 # https://你的用户名.github.io/仓库名

自定义域名（可选）

如果你有域名，可以绑定到 GitHub Pages，实现更专业的访问地址。

# 1. 在仓库的 Settings → Pages 中添加自定义域名 # 2. 在你的域名服务商处添加 DNS 记录 # 添加 CNAME 记录指向：你的用户名.github.io # 例如：blog.example.com → CNAME → username.github.io # 3. 等待 DNS 生效（通常几分钟到几小时） # 4. 勾选 "Enforce HTTPS" 启用强制 HTTPS

GitHub Pages 适用场景：

1. 项目文档网站（GitBook、VuePress 等生成器）

2. 个人博客（Jekyll、Hexo 等静态博客框架）

3. MVP 落地页（纯 HTML/CSS/JS 的静态页面）

4. 开源项目主页（展示项目介绍和使用说明）

GitHub Pages 限制

GitHub Pages 只能托管静态文件（HTML/CSS/JS），不支持后端语言（PHP、Python、Node.js 等）。对于需要后端逻辑的MVP，需要配合 Vercel、Railway 等平台。

五、GitHub Actions

自动化 CI/CD 工作流

GitHub Actions 是 GitHub 内置的自动化工具，可以在代码推送时自动运行测试、构建、部署。对于OPC而言，这意味着每次代码变更都会被自动化验证，省去手动检查的麻烦。

基本概念

概念说明
Workflow（工作流）自动化流程的定义，存储在 .github/workflows 目录
Job（任务）工作流中的一个步骤，可以并行运行
Step（步骤）任务中的具体操作，如检出代码、安装依赖、运行命令
Action（动作）可复用的步骤，市场上有大量预制 Actions
Runner（运行器）执行工作流的服务器（GitHub 提供免费额度）

完整示例：自动部署到 Vercel

# .github/workflows/deploy.yml name: Deploy to Vercel on: push: branches: - main jobs: deploy: runs-on: ubuntu-latest steps: - name: Checkout code uses: actions/checkout@v4 - name: Deploy to Vercel uses: amondnet/vercel-action@v25 with: vercel-token: ${{ secrets.VERCEL_TOKEN }} vercel-org-id: ${{ secrets.VERCEL_ORG_ID }} vercel-project-id: ${{ secrets.VERCEL_PROJECT_ID }} vercel-args: '--prod'

配置 Vercel Secrets

# 1. 在 Vercel Dashboard 获取以下信息： # - Vercel Token: Settings → Tokens # - Org ID: Settings → General → Organization ID # - Project ID: 项目 Settings → General → Project ID # 2. 在 GitHub 仓库添加 Secrets： # Settings → Secrets and variables → Actions → New repository secret # 添加 VERCEL_TOKEN、VERCEL_ORG_ID、VERCEL_PROJECT_ID

自动化测试工作流

# .github/workflows/test.yml name: Test on: push: branches: [ main ] pull_request: branches: [ main ] jobs: test: runs-on: ubuntu-latest strategy: matrix: node-version: [18, 20, 22] steps: - uses: actions/checkout@v4 - name: Use Node.js ${{ matrix.node-version }} uses: actions/setup-node@v4 with: node-version: ${{ matrix.node-version }} cache: 'npm' - name: Install dependencies run: npm ci - name: Run linter run: npm run lint - name: Run tests run: npm test - name: Build project run: npm run build

OPC 建议：先用自动化测试工作流验证代码质量，再逐步添加部署自动化。不要一次性配置太多，让每个环节稳定后再加下一步。

六、实战案例

OPC 典型工作流

案例一 初始化新项目仓库
# 1. 在 GitHub 创建空仓库（不要勾选 README） # 仓库名：my-opc-project # 2. 本地初始化 Git 项目 mkdir my-opc-project && cd my-opc-project git init git remote add origin https://github.com/你的用户名/my-opc-project.git # 3. 创建基础文件 echo "# My OPC Project" > README.md echo "node_modules/" > .gitignore echo "{\"name\": \"my-opc-project\", \"version\": \"1.0.0\"}" > package.json # 4. 首次提交和推送 git add . git commit -m "feat: initial project setup" git branch -M main git push -u origin main
案例二 日常开发流程
# 1. 开始新功能前，先从 main 创建分支 git checkout main git pull origin main git checkout -b feature/user-login # 2. 开发过程中多次提交 git add src/auth/login.js git commit -m "feat: add login form component" git add src/auth/api.js git commit -m "feat: integrate login API" # 3. 功能完成后，推送分支并创建 PR git push origin feature/user-login # 然后在 GitHub 页面创建 Pull Request # 4. 审查通过后合并到 main # 在 GitHub 点击 "Merge" → "Confirm merge" # 5. 切换回 main 并更新 git checkout main git pull origin main git branch -d feature/user-login
案例三 自动化部署静态网站
# 1. 在项目中创建 GitHub Actions 工作流 mkdir -p .github/workflows # 2. 创建部署工作流文件 # .github/workflows/deploy-pages.yml name: Deploy to GitHub Pages on: push: branches: - main jobs: deploy: runs-on: ubuntu-latest steps: - uses: actions/checkout@v4 - name: Setup Pages uses: actions/configure-pages@v4 - name: Upload artifact uses: actions/upload-pages-artifact@v3 with: path: './dist' - name: Deploy to GitHub Pages id: deployment uses: actions/deploy-pages@v4

团队协作模式（OPC为未来准备）

如果未来有合伙人加入，建议使用以下分支策略：

  • main 分支：稳定代码，始终可部署
  • develop 分支：开发中的下一版本
  • feature/* 分支：具体功能开发
  • hotfix/* 分支：紧急Bug修复

每次合并到 main 前都通过 PR 进行代码审查，确保代码质量。

七、国内用户特别指南

网络问题与备选方案

GitHub 在大陆访问不稳定，这是每位OPC都必须面对的问题。本节提供实用的解决方案。

网络问题解决方案

问题解决方案
网页加载慢或无法访问配置 Clash 代理，设置为全局或规则模式
Git 克隆/推送失败设置 Git 代理：git config --global http.proxy http://127.0.0.1:7890
Actions 运行超时使用代理或 Gitee 做国内镜像
SSH 连接不稳定改用 HTTPS 克隆，使用 Personal Access Token 认证

Git 代理配置

# 1. 确保 Clash 开启了 HTTP 代理（默认端口 7890） # 2. 配置 Git 代理 # HTTP/HTTPS 代理 git config --global http.proxy http://127.0.0.1:7890 git config --global https.proxy http://127.0.0.1:7890 # 3. 验证配置 git config --global --get http.proxy git config --global --get https.proxy # 4. 克隆仓库测试 git clone https://github.com/你的用户名/你的仓库.git # 5. 如果不需要代理了，删除配置 git config --global --unset http.proxy git config --global --unset https.proxy

Gitee 备份策略

对于重要项目，建议同时在 Gitee（码云）创建镜像仓库，实现双平台备份。Gitee 是国内的代码托管平台，访问速度稳定。

# 1. 注册 Gitee 账号：https://gitee.com # 2. 在 Gitee 创建同名仓库 # 3. 添加 Gitee 为第二个 remote git remote add gitee https://gitee.com/你的用户名/仓库名.git # 4. 推送到两个平台 git push origin main # GitHub git push gitee main # Gitee # 5. 或者设置同时推送到两个平台 git remote set-url --add origin https://gitee.com/你的用户名/仓库名.git # 验证 git remote -v # 应该显示两个 push 地址

OPC 备份建议：

1. 公开项目：GitHub 为主，Gitee 为备

2. 私有项目：GitHub 为主，可考虑 GitLab 或 Gitee

3. 重要数据：本地也要有备份，使用外接硬盘

4. 定期同步：建议每周执行一次 git push 同步

八、常见问题

FAQ

Q: 私有仓库收费吗？

A: GitHub 免费账户可以创建无限个私有仓库，但每个仓库只能有一个协作者（免费版）。如果需要多人协作，需要升级到付费计划（约 4美元/月）。对于OPC而言，免费版完全够用。

Q: Git 和 GitHub 有什么区别？

A: Git 是版本控制工具（软件），在本地运行。GitHub 是代码托管平台（网站），在云端运行。Git 相当于"本地档案管理系统"，GitHub 相当于"云端档案管理系统"。你可以只用 Git 管理代码，也可以只用 GitHub 网页操作，而两者结合使用是最推荐的方案。

Q: 如何选择分支命名？

A: 建议使用语义化的分支命名规范：

# 功能分支 feature/user-authentication feature/payment-integration # Bug修复分支 bugfix/login-error hotfix/server-crash # 发布分支 release/v1.0.0 release/v1.1.0

Q: 提交信息怎么写比较好？

A: 使用约定式提交（Conventional Commits）格式：

# 格式：type(scope): description # type: feat/fix/docs/style/refactor/test/chore # 示例 feat(auth): add login with wechat fix(api): handle null response in getUser docs(readme): update installation guide refactor(utils): extract common helpers

Q: 误删分支后怎么恢复？

A: 如果分支被合并后删除，可以从 GitHub 网页恢复：

# 1. 在 GitHub 仓库页面点击分支选择器 # 2. 点击 "View all branches" # 3. 找到已删除的分支，点击 "Restore" # 或者用命令行 git checkout -b feature/deleted-branch 提交的SHA

Q: GitHub Actions 免费额度够用吗？

A: GitHub 免费账户每月有 2000 分钟的 Actions 运行时间（自托管运行器无限制）。对于中小型项目，这个额度完全够用。如果超时，可以申请开源项目免费计划。

Q: 如何回滚错误的提交？

A: 使用 git revert 创建一个新的提交来撤销之前的提交（安全方式，不会删除历史）：

# 找到要撤销的提交哈希 git log --oneline # 撤销指定提交（会创建一个新提交） git revert 提交的SHA # 推送撤销 git push origin main

快速开始 Checklist

  • 注册 GitHub 账号（配置网络代理）
  • 安装 Git（Windows: git-scm.com, Mac: 已预装）
  • 配置 Personal Access Token 认证
  • 创建第一个仓库并提交代码
  • 学习 add-commit-push 基础流程
  • 创建第二个分支练习分支操作
  • 配置 GitHub Actions 自动化测试
  • 启用 GitHub Pages 部署静态网站

记住：GitHub 是OPC的"代码中央银行"。定期提交、双平台备份、自动化验证，这三件事做好，开发流程就不会出大问题。
