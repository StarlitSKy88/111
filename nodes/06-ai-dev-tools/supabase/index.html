Supabase

开源 Firebase 替代方案。PostgreSQL 数据库 + 身份认证 + 文件存储 + Edge Functions，一站式后端服务，适合 OPC 快速上线 MVP。

更新于 2026-05-14 · 版本：Supabase v2
01

核心定位

Supabase 是一个开源的 "Firebase 替代品"，但底层使用的是 PostgreSQL——业界最强大的开源关系型数据库。与 Firebase 的 NoSQL 不同，Supabase 鼓励使用标准 SQL，让你对自己的数据有完全的控制权。

四大核心模块

Database

PostgreSQL + 自动 REST API

自动为每个表生成 CRUD REST API，支持实时订阅，零配置即可操作数据。

Auth

身份认证与授权

开箱即用的邮箱/密码登录、OAuth 第三方登录（Google、GitHub 等）、Row Level Security 行级安全策略。

Storage

文件存储与 CDN

支持图片、视频、文件的存储与分发，自动搭配 CDN 加速下载。

Edge Functions

边缘计算 Serverless

Deno runtime 的 Serverless 函数，部署在全球边缘节点，响应延迟更低。

什么时候选择 Supabase？

需要快速上线 MVP、团队小于 5 人、不想维护服务器、期望免费额度够用的项目。Supabase 的免费额度（500MB 数据库、1GB 存储、50MB 文件上传限制）可以支撑初期产品。

与 Firebase 对比

03

数据库

Supabase 的核心是 PostgreSQL。在 Dashboard 的 Table Editor 中可以图形化建表，也可以用 SQL Editor 写原生 SQL。

建表

推荐用 SQL Editor 创建表，这样可以版本化管理（配合 Git）。

-- 创建 profiles 表（对应用户扩展信息） CREATE TABLE profiles ( id UUID REFERENCES auth.users(id) ON DELETE CASCADE PRIMARY KEY, username TEXT UNIQUE NOT NULL, avatar_url TEXT, created_at TIMESTAMPTZ DEFAULT NOW(), updated_at TIMESTAMPTZ DEFAULT NOW() ); -- 创建 posts 表 CREATE TABLE posts ( id BIGSERIAL PRIMARY KEY, user_id UUID REFERENCES profiles(id) ON DELETE CASCADE, title TEXT NOT NULL, content TEXT, published BOOLEAN DEFAULT FALSE, created_at TIMESTAMPTZ DEFAULT NOW() ); -- 启用 Row Level Security ALTER TABLE profiles ENABLE ROW LEVEL SECURITY; ALTER TABLE posts ENABLE ROW LEVEL SECURITY;

自动 REST API

每个表会自动生成 CRUD REST API，终点格式为：

GET /rest/v1/posts -- 获取所有 posts GET /rest/v1/posts?id=eq.1 -- 条件查询 POST /rest/v1/posts -- 创建 post PATCH /rest/v1/posts?id=eq.1 -- 更新 post DELETE /rest/v1/posts?id=eq.1 -- 删除 post

前端查询示例

// 获取所有已发布的文章 const { data, error } = await supabase .from('posts') .select('*, profiles(username, avatar_url)') .eq('published', true) .order('created_at', { ascending: false }) .limit(10) // 创建新文章 const { data, error } = await supabase .from('posts') .insert({ user_id: user.id, title: '我的第一篇文章', content: '内容在这里...', published: false })

实时订阅

使用 Supabase 的实时功能，可以让前端自动感知数据库变化。

// 监听 posts 表的插入事件 const channel = supabase .channel('posts-changes') .on( 'postgres_changes', { event: 'INSERT', schema: 'public', table: 'posts' }, (payload) => { console.log('New post:', payload.new) } ) .subscribe()

OPC 实战建议：用 Supabase 做博客、笔记、社区、待办清单等项目，数据结构清晰，REST API 直接可用，省去后端开发时间。

04

身份认证

Supabase Auth 提供完整的身份认证方案，包括邮箱密码登录、OAuth 第三方登录、以及基于 Row Level Security 的数据访问控制。

邮箱密码登录

// 注册 const { data, error } = await supabase.auth.signUp({ email: 'user@example.com', password: 'secure-password' }) // 登录 const { data, error } = await supabase.auth.signInWithPassword({ email: 'user@example.com', password: 'secure-password' }) // 登出 await supabase.auth.signOut()

OAuth 第三方登录

在 Dashboard → Authentication → Providers 中启用 Google、GitHub 等提供商，然后：

// GitHub 登录 const { data, error } = await supabase.auth.signInWithOAuth({ provider: 'github', options: { redirectTo: 'https://yourapp.com/auth/callback' } })

获取当前用户

// 获取当前会话（页面加载时优先调用） const { data: { session } } = await supabase.auth.getSession() // 获取当前用户（含元数据） const { data: { user } } = await supabase.auth.getUser() // 监听认证状态变化 supabase.auth.onAuthStateChange((event, session) => { if (event === 'SIGNED_IN') { console.log('User signed in:', session.user) } })

Row Level Security (RLS)

RLS 是 Supabase 的核心安全特性。定义哪些行对哪些用户可见/可操作。

-- profiles 表：用户只能读写自己的数据 CREATE POLICY "Users can view own profile" ON profiles FOR SELECT USING (auth.uid() = id); CREATE POLICY "Users can update own profile" ON profiles FOR UPDATE USING (auth.uid() = id); -- posts 表：只能查看已发布的、只能修改自己的 CREATE POLICY "Anyone can view published posts" ON posts FOR SELECT USING (published = true OR auth.uid() = user_id); CREATE POLICY "Users can insert own posts" ON posts FOR INSERT WITH CHECK (auth.uid() = user_id); CREATE POLICY "Users can update own posts" ON posts FOR UPDATE USING (auth.uid() = user_id); CREATE POLICY "Users can delete own posts" ON posts FOR DELETE USING (auth.uid() = user_id);

重要：一定要为每个启用了 RLS 的表创建明确的 POLICY。如果不创建 POLICY，默认是拒绝所有操作。

05

文件存储

Supabase Storage 用于存储图片、视频、PDF 等文件，支持公开访问或私有访问，自动搭配全球 CDN。

创建 Bucket

在 Dashboard → Storage 中创建 bucket，或者用 SQL：

INSERT INTO storage.buckets (id, name, public) VALUES ('avatars', 'avatars', true);

上传文件

// 从文件选择器获取文件 const fileInput = document.getElementById('avatar') const file = fileInput.files[0] const { data, error } = await supabase.storage .from('avatars') .upload(`user-${user.id}/avatar.jpg`, file)

获取公开 URL

const { data } = supabase.storage .from('avatars') .getPublicUrl(`user-${user.id}/avatar.jpg`) // data.publicUrl 即为公开访问地址 console.log(data.publicUrl)

上传并转换公开 URL

const { data, error } = await supabase.storage .from('avatars') .upload(file, { cacheControl: '3600', upsert: false })

Storage 权限（RLS）

Storage 也有 RLS 策略，控制文件访问权限。

-- 允许所有人查看 avatars bucket 中的公开文件 CREATE POLICY "Public read access for avatars" ON storage.objects FOR SELECT USING (bucket_id = 'avatars'); -- 允许用户只上传和修改自己的头像 CREATE POLICY "Users can upload own avatar" ON storage.objects FOR INSERT WITH CHECK ( bucket_id = 'avatars' AND auth.uid()::text = (storage.foldername(name))[1] );
06

Edge Functions

Edge Functions 是 Supabase 的 Serverless 函数，基于 Deno runtime，部署在全球边缘节点，响应速度快。

适用场景

  • 需要调用第三方 API（不暴露 secret key）
  • 复杂的数据转换或计算
  • 需要定时任务（结合 pg_cron）
  • Webhook 接收与处理

部署函数

# 安装 Supabase CLI npm install -g supabase # 登录 supabase login # 初始化函数项目 supabase functions new my-function # 编辑代码后部署 supabase functions deploy my-function

示例函数

// supabase/functions/my-function/index.ts import { serve } from 'https://deno.land/std@0.168.0/http/server.ts' serve(async (req) => { const { name } = await req.json() return new Response( JSON.stringify({ message: `Hello, ${name}!` }), { headers: { 'Content-Type': 'application/json' } } ) })

调用 Edge Function

const { data, error } = await supabase.functions.invoke('my-function', { body: { name: 'OPC' } })

OPC 注意：Edge Functions 是调用外部 API 的安全中间层。例如微信支付需要签名验证，就可以在 Edge Function 中完成，不暴露商户密钥。

实战案例

案例一：连接前端

一个完整的 Supabase + 前端集成示例（以博客为例）：

// lib/supabase.ts import { createClient } from '@supabase/supabase-js' const supabaseUrl = import.meta.env.VITE_SUPABASE_URL const supabaseKey = import.meta.env.VITE_SUPABASE_ANON_KEY export const supabase = createClient(supabaseUrl, supabaseKey) // hooks/useAuth.ts import { useState, useEffect } from 'react' import { supabase } from '../lib/supabase' export function useAuth() { const [user, setUser] = useState(null) const [loading, setLoading] = useState(true) useEffect(() => { supabase.auth.getSession().then(({ data: { session } }) => { setUser(session?.user ?? null) setLoading(false) }) const { data: { subscription } } = supabase.auth.onAuthStateChange( (_event, session) => { setUser(session?.user ?? null) } ) return () => subscription.unsubscribe() }, []) return { user, loading } }

案例二：完整 Auth Flow

// 1. 注册时同时创建 profile（使用 Database Trigger） CREATE OR REPLACE FUNCTION public.handle_new_user() RETURNS TRIGGER AS $$ BEGIN INSERT INTO public.profiles (id, username) VALUES ( NEW.id, COALESCE(NEW.raw_user_meta_data->>'username', 'user_' || substr(NEW.id::text, 1, 8)) ); RETURN NEW; END; $$ LANGUAGE plpgsql SECURITY DEFINER; CREATE TRIGGER on_auth_user_created AFTER INSERT ON auth.users FOR EACH ROW EXECUTE FUNCTION public.handle_new_user(); // 2. 前端注册 async function signUp(email: string, password: string) { const { data, error } = await supabase.auth.signUp({ email, password, options: { data: { username: email.split('@')[0] } } }) // 自动触发 trigger，创建 profile } // 3. 前端登录后自动跳转 supabase.auth.onAuthStateChange((event, session) => { if (event === 'SIGNED_IN' && session) { router.push('/dashboard') } })

案例三：数据库 Schema 设计

一个任务管理工具的最小数据模型：

-- 用户表（自动通过 auth.users 关联） CREATE TABLE public.profiles ( id UUID PRIMARY KEY REFERENCES auth.users(id) ON DELETE CASCADE, username TEXT UNIQUE NOT NULL, created_at TIMESTAMPTZ DEFAULT NOW() ); -- 项目表 CREATE TABLE public.projects ( id BIGSERIAL PRIMARY KEY, owner_id UUID REFERENCES profiles(id) ON DELETE CASCADE, name TEXT NOT NULL, description TEXT, created_at TIMESTAMPTZ DEFAULT NOW() ); -- 任务表 CREATE TABLE public.tasks ( id BIGSERIAL PRIMARY KEY, project_id BIGINT REFERENCES projects(id) ON DELETE CASCADE, assignee_id UUID REFERENCES profiles(id) ON DELETE SET NULL, title TEXT NOT NULL, status TEXT DEFAULT 'todo' CHECK (status IN ('todo', 'in_progress', 'done')), due_date DATE, created_at TIMESTAMPTZ DEFAULT NOW() ); -- RLS 策略 ALTER TABLE public.profiles ENABLE ROW LEVEL SECURITY; ALTER TABLE public.projects ENABLE ROW LEVEL SECURITY; ALTER TABLE public.tasks ENABLE ROW LEVEL SECURITY; -- 用户只能看到自己参与的项目和任务 CREATE POLICY "Users can manage own projects" ON public.projects FOR ALL USING (owner_id = auth.uid()); CREATE POLICY "Users can view project tasks" ON public.tasks FOR SELECT USING ( project_id IN ( SELECT id FROM public.projects WHERE owner_id = auth.uid() ) OR assignee_id = auth.uid() );

常见问题

免费额度够用吗？

对于 MVP 阶段的个人项目，免费额度基本够用。500MB 数据库可以存储数万条记录，1GB 存储空间可以存几百张图片。月活跃用户无限制，超出用量才收费。

数据安全吗？会被攻击吗？

Supabase 自身提供基础安全防护，但关键在于正确的 RLS 配置。确保所有表都启用 RLS 并创建明确的 POLICY，不要依赖"默认允许"来工作。

可以自托管吗？

可以。Supabase 是 100% 开源的，你可以使用 Docker 在自己的服务器上部署完整实例。但这需要额外的运维工作，对于 OPC 来说，直接使用云服务是更好的选择。

和 Parse、Backendless 比怎么样？

Supabase 使用 PostgreSQL，数据可控性强，社区活跃，文档完善。Parse 近年来维护较少，Backendless 是商业闭源。Supabase 是目前最推荐的 Parse 替代品。

支持中文吗？文档有中文吗？

官方文档是英文的，但网上有大量中文教程。Dashboard 有中文界面。PostgreSQL 本身对中文搜索有良好的支持（使用 ILIKE 或全文检索）。

文件上传大小限制？

免费版单文件最大 50MB，付费版（Pro）可到 5GB。如果需要上传大文件，可以考虑将文件切片上传，或者使用专门的云存储（如 Cloudflare R2，免费额度更大）。

如何备份数据？

在 Dashboard → Database → Backups 中可以手动触发备份。付费版支持自动备份。也可以使用 pg_dump 自行导出备份。

国内访问速度如何？

Supabase 的服务器主要在海外（美国、欧洲、亚太），国内访问延迟较高。对于纯国内项目，可以考虑 Supabase 的自托管方案，或者使用腾讯云 + PostgreSQL 的组合。

Supabase 快速检查清单

  • 创建项目，保存 API URL 和 anon key 到 .env
  • 用 SQL Editor 创建表，启用 RLS
  • 配置 Auth（邮箱登录或 OAuth）
  • 设置 Storage bucket 和权限
  • 如需外部 API，部署 Edge Function
  • 前端集成，测试完整 Auth Flow

一句话总结：Supabase 让 OPC 可以用一套工具搞定数据库、认证、存储三大后端需求，大幅加速 MVP 开发。
