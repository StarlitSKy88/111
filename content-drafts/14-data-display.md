# 节点14：数据展示与交互

> **面向OPC**：你做了功能，也存了数据，但用户打开页面看到一堆文字和数字就跑。怎么用最少的代码，让数据"自己会说话"？

---

## 一、OPC的数据展示第一原理

### 一个残酷的事实

用户在页面上停留的前3秒决定去留。3秒内没看懂的页面 = 用户关掉。

**OPC的独特优势**：你不是大公司，不需要做"数据大屏"。你只需要让用户看懂**一个数字 + 一个趋势**。

### 黄金公式

> **好的数据展示 = 1个大数字 × 1个趋势图 × 0个多余元素**

- 大数字：48px以上，放在页面最上方，一眼看到
- 趋势图：一个简单的折线图或柱状图，展示"在变好"
- 0个多余：不要筛选器、不要导出按钮、不要对比视图

**反面案例**：某OPC做了一个数据分析页，有7个筛选器、4种图表、3个导出格式。上线后DAU为零——因为用户打开页面后不知道看哪里。

**正面案例**：同样是这个OPC，把数据页砍到只剩"本周收入 ¥1,247"一个大数字 + 一个7天收入折线图。DAU翻了三倍。

## 二、2026年最省力的数据可视化方案

### 场景1：纯静态页面 / 原生JS → Chart.js v5

```html
<!-- 10分钟从零到可用的柱状图 -->
<script src="https://cdn.jsdelivr.net/npm/chart.js@5"></script>
<canvas id="myChart" width="400" height="200"></canvas>
<script>
new Chart(document.getElementById('myChart'), {
  type: 'bar',
  data: {
    labels: ['周一','周二','周三','周四','周五','周六','周日'],
    datasets: [{ label: '访问量', data: [12,19,8,27,15,35,42] }]
  }
});
</script>
```

**为什么选它**：CDN引入零安装、60KB体积、中文文档完善、2026年v5支持Tree Shaking按需加载。

### 场景2：React / Next.js → Recharts

```jsx
import { LineChart, Line, XAxis, YAxis, Tooltip } from 'recharts';
<LineChart width={600} height={300} data={data}>
  <XAxis dataKey="date" />
  <YAxis />
  <Tooltip />
  <Line type="monotone" dataKey="value" stroke="#C0392B" />
</LineChart>
```

**为什么选它**：组件式声明（声明即所得）、样式直接用CSS控制、天然支持响应式。

### 场景3：需要中国地图 → ECharts（按需引入）

```html
<script src="https://cdn.jsdelivr.net/npm/echarts@5/dist/echarts.min.js"></script>
```
**仅在使用地图/热力图/桑基图时才选ECharts。** 基础图表用Chart.js完全够用。

## 三、图表选择决策树（实战版）

```
用户想看什么？
│
├─ 看变化 → 折线图（时间轴X，数值Y）
│  例：过去30天注册人数变化
│
├─ 看排名 → 横向柱状图（长条目容易读）
│  例：各功能使用次数排名
│
├─ 看占比 → 只展示TOP3 + "其他"
│  例：用户来源渠道分布
│  注意：永远不要用饼图展示超过5个分类，超过5个用柱状图
│
├─ 看一个数 → 不要图表，直接48px大数字
│  例：本月总收入 ¥12,847
│
└─ 看对比 → 两个大数字并排
   例：本周 vs 上周
```

## 四、三个最常见的数据页面模板

### 模板1：Dashboard概览（任何产品的首页数据区）

```
┌──────────────────────────────────────┐
│  今日收入          本周新增用户       │
│  ¥1,247            +36               │
│  ↑12%              目标50             │
├──────────────────────────────────────┤
│  ▂▃▅▇▆█▊  (过去7天收入趋势折线图)     │
└──────────────────────────────────────┘
```

代码量：~80行HTML+JS（含Chart.js）。开发时间：半天。

### 模板2：个人统计（用户看自己的数据）

```
┌──────────────────────────────────────┐
│  你的累计分析次数：247               │
│  超过了 78% 的用户                   │
├──────────────────────────────────────┤
│  最近7天使用频率 ▂▃▇▆█▅▃             │
│  AI评分趋势 ▁▂▄▅▆▆█                  │
└──────────────────────────────────────┘
```

**关键技巧**："超过xx%用户"的社交比较是留存率最高的设计模式（参考Spotify年度总结）。

### 模板3：管理后台（给管理者看的运营数据）

```
┌──────────┬──────────┬──────────┬──────────┐
│  总用户   │  今日活跃  │  付费用户  │  总收入   │
│  1,247   │   89     │   23     │ ¥4,200   │
└──────────┴──────────┴──────────┴──────────┘
```

四个卡片并排，每个卡片：数字在上（大号），标签在下（小号灰色）。

## 五、交互设计的最小必要集

### 永远要加的三个交互

1. **点击数字看详情**：大数字必须是可点击的，点了展示明细列表
2. **图表hover提示**：鼠标悬停显示具体数值（chart.js 默认就有）
3. **空状态设计**：新用户没有数据时，显示"完成第一次XX后这里会出现数据"，而不是空白页

### 永远不要加的三个"功能"

1. ❌ **日期选择器**：90%用户只用默认的"最近7天"和"最近30天"，放两个切换按钮即可
2. ❌ **导出CSV/Excel**：第一版不要做，等有用户明确要了再说。这一项能省你半天开发时间
3. ❌ **自定义看板/拖拽布局**：功能堆砌，OPC第一版不需要

## 六、移动端适配（一个人也要做）

OPC的产品50%以上的流量来自手机。**数据页面在手机上出问题 = 丢掉一半用户。**

### 响应式三原则

| 桌面端 | 移动端 |
|---|---|
| 4列卡片并排 | 2列卡片（或上下堆叠） |
| 图表宽600px | 图表占满屏幕宽度 |
| 大数字48px | 大数字36px（仍然足够醒目） |

### 一行代码搞定移动端图表

```css
/* Chart.js 自动响应式 */
canvas { max-width: 100%; }

/* Recharts 响应式容器 */
<ResponsiveContainer width="100%" height={200}>
```

## 七、检查清单

- [ ] 页面核心是一个大数字（≥36px移动端 / ≥48px桌面端）
- [ ] 只有一个趋势图（折线或柱状），没有多余图表
- [ ] 没有日期选择器、导出按钮、自定义布局
- [ ] 空状态有引导文案
- [ ] 图表hover能看具体数值
- [ ] 手机横屏/竖屏都正常显示
- [ ] 页面加载≤2秒（图表CDN引入，非打包）
