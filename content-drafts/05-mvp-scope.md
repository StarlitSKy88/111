# 节点05：MVP范围确定

> **面向OPC**：你的想法很好，功能列表写了20条。现在砍到3条——只留那些"不做就会死"的功能。MVP不是"最小产品"，是"最小区间内验证有人愿意付钱"。

---

## 一、2026年OPC的MVP新定义

### 传统定义（已过时）

> Minimum Viable Product = 最小可行产品

### 2026年OPC定义

> Minimum **Valuable** Product = 最小**有价值**产品

区别：Viable（可行）=能用就行。Valuable（有价值）=好到有人愿意付钱。

---

## 二、MVP范围的四刀法

### 第一刀：砍掉所有"以后可能有用"的功能

| 功能 | 砍掉理由 |
|---|---|
| 用户个人中心/头像 | 没有人因为"可以换头像"而付费 |
| 暗色模式 | 上线后再做（一行CSS的事） |
| 数据导出CSV | 等有人问了再做 |
| 多语言 | 中文用户够你吃一年 |
| 消息通知系统 | 先用微信群代替 |

**砍完这一刀，功能列表从20条变成6条。**

### 第二刀：只留"用户核心任务"

问自己：**用户打开我的产品，是为了完成什么任务？**

- 如果3秒内说不出来 → 这个功能砍掉
- 如果用户不用这个功能也能完成任务 → 砍掉

**砍完这一刀，6条变成3条。**

### 第三刀：3条里选1条最先做

剩下的3条核心功能，按"用户最痛的问题"排序。只做第一条，其他两条用文字先标注"即将上线"。

**砍完这一刀，只剩下1个核心功能 + 2个文字占位。**

### 第四刀：这1个功能，只做80%

一个功能有"基本流程"和"各种边界情况"。MVP只做基本流程：

| 基本流程（MVP必做） | 边界情况（MVP不做） |
|---|---|
| 用户上传简历→AI分析→显示评分 | 上传PDF格式不对时的提示 |
| 用户下单→微信支付→支付成功 | 支付超时后的自动退款 |
| 用户输入→AI生成→展示结果 | 输入超过1000字时的截断处理 |

---

## 三、MVP范围文档模板

```markdown
# [产品名] MVP

## 一句话价值主张
[动词] + [对象] + [结果]

## 核心指标（上线后2周内必须达到）
- 注册用户：≥50人
- 核心功能使用率：≥40%（注册用户中使用核心功能的比例）
- 用户反馈中"愿意付费"的比例：≥20%

## MVP功能清单
### P0（必须有）
1. [核心功能1的80%]
2. 注册/登录
3. 页面能正常打开（无白屏）

### P1（最好有，没有也能上）
4. [占位功能2：标注"即将上线"]
5. [占位功能3：标注"即将上线"]

## 明确不做（P2+）
- 暗色模式
- 数据导出
- 个人中心
- 消息通知
- 多语言
```

## 四、2026年MVP开发时间锚

| 产品类型 | MVP最长开发时间 | 超过这个时间=你做的不是MVP |
|---|---|---|
| AI工具/内容站 | 1-2周 | 用v0/Cursor加速，1周够了 |
| SaaS | 2-4周 | 用Supabase省掉后端时间 |
| 微信小程序 | 2-4周 | 含审核时间 |
| 电商 | 2-4周 | 用现成模板 |

**如果4周做不完→范围砍得不够狠。回去继续砍。**
