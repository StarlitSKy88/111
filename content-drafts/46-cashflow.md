# 节点46：现金流与财务基础

> **面向OPC**：一人公司没有投资人兜底。现金流就是你还能活多久的倒计时器。本章不讲会计学原理，只讲三件事——你的钱在哪儿、还能撑多久、什么时候能辞职全职干。

## 💰 交互工具一：盈亏平衡计算器

*（注：此工具将在 HTML 页面中以嵌入式 JS 实现，逻辑如下）*

### 计算器逻辑

用户输入以下四个数值，实时计算出三条关键结果：

| 输入字段 | 说明 | 示例 |
|---|---|---|
| **月固定支出** | 房租、服务器、SaaS订阅、代账费、社保（必填） | ¥8,000 |
| **月生活支出** | 房租/房贷、吃饭、交通（必填） | ¥6,000 |
| **产品月收入** | 当前每月进账（选填） | ¥5,000 |
| **当前存款** | 银行卡余额（选填） | ¥50,000 |

### 实时输出

| 结果 | 公式 | 含义 |
|---|---|---|
| **盈亏平衡点** | 月固定支出 + 月生活支出 | 你每月至少需要赚多少钱才不亏 |
| **现金跑道** | 当前存款 ÷ 盈亏平衡点 | 如果今天起零收入，你还能撑几个月 |
| **缺口/盈余** | 产品月收入 − 盈亏平衡点 | 每月是亏是赚，差多少 |

### 输出解读

| 现金跑道 | 状态 | 行动 |
|---|---|---|
| **> 12个月** | 🟢 安全 | 有充足时间试错，可以适度投资增长 |
| **6-12个月** | 🟡 注意 | 加速验证商业模式，控制非必要支出 |
| **3-6个月** | 🟠 警戒 | 暂停所有弹性支出，全力推动收入增长 |
| **< 3个月** | 🔴 危险 | 立即启动增收/砍支，考虑兼职维持生计 |

## 📒 交互工具二：简易流水记账

*（注：此工具将在 HTML 页面中以嵌入式 JS 实现，逻辑如下）*

### 工具设计

一个极简的三栏式记账面板，OPC 无需注册、无需后端、数据存储在浏览器 localStorage 中。

### 界面要素

```
┌─────────────────────────────────────────────────┐
│  📅 日期    │  💰 金额  │  📝 说明      │  +  │
│  2026-05-09 │  -500    │  服务器续费    │  ✕  │
│  2026-05-08 │ +3,200   │  客户A项目款   │  ✕  │
│  2026-05-07 │  -150    │  域名续费      │  ✕  │
├─────────────────────────────────────────────────┤
│  📊 本月收入: ¥3,200  │  📉 本月支出: ¥650  │
│  💵 本月净额: +¥2,550                        │
├─────────────────────────────────────────────────┤
│  [导出CSV]  [清除本月]  [查看全部历史]        │
└─────────────────────────────────────────────────┘
```

### 功能

- **添加记录**：输入日期/金额/说明，一键添加
- **收支分类**：正数为收入，负数为支出
- **自动汇总**：实时显示本月收入/支出/净额
- **数据持久化**：浏览器 localStorage 存储，刷新不丢失
- **导出 CSV**：一键导出所有记录为 CSV 文件（可用于报税或交给代账公司）
- **数据清除**：可清除单条、本月、或全部记录

### 为什么不用 Excel

这个工具存在的意义不是替代专业财务软件，而是让你养成"每笔钱都记"的习惯。数据最终导出 CSV 后仍会交给代账公司——但在此之前，你需要一个打开即用的零摩擦工具。

## 一、OPC唯一需要懂的财务概念：现金流

### 三张表里你只需要关心一张

会计学有三张表：资产负债表、利润表、现金流量表。对一人公司来说：

| 表 | 需要懂吗 | 为什么 |
|---|---|---|
| **利润表** | ⚠️ 看懂就行 | 账面上赚了钱 ≠ 口袋里有钱（客户欠你30万但账期90天，你照样付不起房租） |
| **资产负债表** | ❌ 先不管 | 等你公司超过3个人再看 |
| **现金流量表** | ✅ **必须盯** | 这是你公司的心电图。断流 = 死亡 |

### OPC现金流铁律

> **利润是纸面的，现金流才是真实的。**

你签了一个5万的合同 ≠ 你有5万。钱到账那天才算数。

## 二、现金跑道：你还能活多久

### 公式

```
现金跑道（月）= 当前存款 ÷ 月固定总支出
```

- **当前存款**：公司对公账户 + 个人账户中可用于维持运营的钱
- **月固定总支出**：公司的刚性支出 + 你的最低生活支出

### 四级预警

| 跑道 | 等级 | 必须做的事 |
|---|---|---|
| **> 12个月** | 🟢 | 正常运营，持续验证商业模式 |
| **6-12个月** | 🟡 | 每月复盘：跑道是拉长了还是缩短了 |
| **3-6个月** | 🟠 | 立刻暂停所有弹性支出，全力推动回款 |
| **< 3个月** | 🔴 | 生存模式：只保留能直接产生收入的支出，其余全砍。同时启动副流收入 |

### 跑道被低估的五大元凶

| 隐藏项 | 月均金额 | 你算进去了吗？ |
|---|---|---|
| 自雇社保（养老+医疗） | ¥1,500-3,000 | ⚠️ 经常被遗漏 |
| 个税预提 | 收入的5%-15% | ⚠️ 季末才发现 |
| SaaS订阅膨胀 | ¥500-2,000 | ⚠️ "反正不贵"的累积效应 |
| 设备折旧/替换 | ¥300-800 | ⚠️ 电脑坏的那天才想起来 |
| 代理记账费 | ¥200-400 | ⚠️ 年付容易忘 |

**你的真实月支出 = 你以为的 × 1.3。** 计算跑道时请乘以1.3的安全系数。

## 三、盈亏平衡：每个月至少要赚多少

### 公式

```
月盈亏平衡点 = 刚性支出 + 弹性支出 + 隐性支出 + 个人生活支出
```

### 拆解

| 类别 | 典型项目 | OPC月均范围 |
|---|---|---|
| **刚性支出** | 服务器、域名、SaaS工具、代账、注册地址 | ¥1,500-5,000 |
| **弹性支出** | 广告投流、外包、付费课程 | ¥1,000-5,000 |
| **隐性支出** | 社保、税款预提、设备折旧摊销 | ¥2,000-5,000 |
| **个人生活** | 房租、吃饭、交通 | ¥4,000-15,000（视城市） |

**一线城市OPC**：月盈亏平衡约 ¥12,000-20,000
**二三线城市OPC**：月盈亏平衡约 ¥8,000-12,000

### 缩减支出的优先级

当需要砍支出时，按此顺序：

1. 先砍弹性支出（广告、课程、外包）
2. 再砍SaaS订阅（用免费替代、停用测试）
3. 再砍非必要刚性（换更便宜的注册地址方案）
4. **绝不砍**：代理记账、社保、税款预提

## 四、"何时能全职"：一套可操作的判断逻辑

### 不是"赚到X万就辞职"

辞职全职创业需要同时满足三个条件：

### 条件一：产品月收入覆盖个人生活支出

> 你的产品每个月稳定进账 ≥ 你的房租+吃饭+交通

**不是某一两个月**，而是看**连续6个月**的平均值。如果某月¥30,000、下月¥0，不算稳定。

### 条件二：现金跑道 ≥ 12个月

> 在零新增收入的情况下，你的存款够你维持12个月的生存

这12个月的缓冲不是让你躺平，是让你在连续两个月收入为零的时候仍然有试错空间。

### 条件三：有至少两个收入来源

> 不要把全部收入押在一个客户或一个产品上

- 主产品收入 + 一个副流（咨询/外包/课程）
- 或：产品收入 + 存款利息/投资收入
- 或：产品对公收入 + 伴侣/家人稳定收入

**满足三个条件 → 可以全职。** 否则 → 继续兼职验证。

## 五、三账户隔离：钱的物理防火墙

### 比任何记账软件都重要的习惯

把公司的钱和个人的钱分开——不是"心理上"分开，是**物理上**分开。三个独立账户：

### 账户一：运营账户（对公账户）

> 所有客户付款进这里，所有业务支出来自这里。

- 服务器续费、SaaS订阅、外包付款全部从这个账户出
- 每周核查一次余额，确保覆盖未来30天的预计支出
- 从运营账户给自己转工资（每月固定一笔），不要随用随转

### 账户二：储备账户（个人储蓄账户）

> "如果明天起零收入，这个账户能撑多久"的答案。

- 目标金额：**8个月的刚性支出 + 个人生活费**
- 达到目标前：每月收入的30-40%强制转入
- 达到目标后：只在重大消耗时才补充
- **只进不出**，除非遇到真正的生存危机

### 账户三：税务账户

> 税款不是"挣到的钱"，是"暂时替你保管的钱"。

每笔收入到账时，**立刻将20-25%转入税务账户**。季度末缴税时，这笔钱已经准备好了，不会出现"要交5万但账上只有2万"的绝境。

### 三账户分割比例

| 账户 | 每笔进账分配 | 用途 |
|---|---|---|
| **运营账户** | 55-65% | 日常经营支出 |
| **储备账户** | 20-25% | 安全垫积累 |
| **税务账户** | 15-20% | 季度税款预提 |

## 六、预收款不是收入：OPC最容易踩的坑

### 错误认知

> "客户付了12000元年费！这个月收入12000！"

### 正确认知

客户一次付了12个月年费¥12,000。但你每个月交付一次服务——所以你每个月只能确认¥1,000的收入。

- 到账¥12,000 → 记入"预收账款"（**这是负债，不是你的钱**）
- 每月服务交付 → 从预收账款转¥1,000到"已确认收入"
- 12个月后 → ¥12,000才全部转化为你的收入

### 为什么这么重要

金税四期下，开票金额与申报收入自动比对。如果你第一个月就把¥12,000全申报为收入——当月多交税，后面11个月没收入申报触发异常预警。

## 七、订阅审计：每季度做一次"停用测试"

### 典型的OPC SaaS账单

| 工具 | 月费 | 上月打开次数 |
|---|---|---|
| Cursor Pro | $20 | 每天 |
| Claude Max | $200 | 每周2次 |
| Notion Plus | $10 | 0次（改用飞书了） |
| Canva Pro | $13 | 2次 |
| 某AI出图工具 | $15 | 0次（上个月用了一次后就忘了） |
| 某数据分析工具 | $30 | 0次（免费试用后忘记取消） |

这个账单里，Notion、AI出图、数据分析工具三个月没打开，每年浪费 (10+15+30) × 12 = **$660（约¥4,800）**。

### 停用测试流程

每季度末：
1. 列出所有订阅的SaaS，标注月费和上月打开次数
2. 对"上月打开0次"的工具 → **立即暂停**
3. 暂停两周，看业务是否受影响
4. 两周无感知 → **永久取消**
5. 有影响 → 恢复订阅，但明确它的不可替代价值

## 九、季度压力测试

### 每季度末问自己三个问题

**问题一**：如果最大客户明天流失，现金跑道还剩多少？

**问题二**：如果所有客户的账期延长30天，现金流能否支撑？

**问题三**：如果连续两个月零新客户，第三个会发生什么？

### 任一回答触达红线 → 立刻启动防御

- 暂停所有非核心SaaS订阅
- 加速催收应收账款
- 减少非必需外包
- 启动副流收入
- 重新评估价格策略

## 总纲

OPC的财务系统不需要复杂。你只需要：

| 层级 | 工具 | 做什么 |
|---|---|---|
| **每日** | 三账户隔离 | 每笔进账自动分流 |
| **随时** | 本页计算器 | 输入两个数字就知道跑道和缺口 |
| **每周** | 简易记账工具 | 记录收支，导出CSV |
| **每月** | 代账公司 | 申报纳税 |
| **每季** | 停用测试 + 压力测试 | 砍掉不用的订阅、模拟最坏情况 |

> 现金流管理不是月底回顾，而是嵌入日常的前哨系统。你今天记的一笔账，可能是三个月后救你命的预警。
