# 节点29：审核问题处理

> **面向OPC**：审核被打回了。别慌——这不是失败，这是"平台免费帮你做了一次QA"。每个被打回的审核问题，都是在告诉你"这个地方会让用户不满"。

---

## 一、解读审核反馈：翻译官上线

审核反馈通常写得很官方。以下是最常见的打回原因及真实含义：

| 审核员写的 | 真实含义 | 修改方向 |
|---|---|---|
| "功能不完整" | 你提交的版本有页面空白/按钮无响应 | 走一遍核心路径，确保每个按钮都有反应 |
| "类目不符" | 你选的类目和实际功能不匹配 | 重新选择与核心功能最接近的类目 |
| "缺少必要资质" | 你的功能涉及需要许可证的行业 | 上传相关资质，或者暂时去掉该功能 |
| "存在测试数据" | 审核员看到了开发中留下的假数据 | 清空所有测试数据，填充真实内容 |
| "用户体验不足" | 界面太简陋或操作逻辑混乱 | 参考同类已过审产品的最低标准 |
| "涉及未开放能力" | 你用了平台暂未开放给个人开发者的API | 换成替代方案 |

---

## 二、打回后的处理SOP（标准操作流程）

### 步骤1：冷静分析（10分钟）

打开审核反馈，逐条回答三个问题：

1. **问题具体在哪里？** → 打开产品，找到审核员指出的页面/功能
2. **为什么被打回？** → 对照平台的审核规范文档
3. **怎么改？** → 写一句话的修改方案

### 步骤2：修改实施（越快越好）

```
修改原则：
- 只改被打回的地方，不趁机"顺便优化"
- 如果一个问题需要大改（超过1天），考虑先去掉该功能，过审后再加
- 修改后跑节点18的核心路径测试
```

### 步骤3：准备重新提交

除了修改代码，还需要写一份**修改说明**：

```
修改说明模板：
"感谢审核反馈。针对打回原因，我们做了以下修改：
1. [打回原因1]：已[做了什么修改]，见[截图或说明]
2. [打回原因2]：已[做了什么修改]，见[截图或说明]
如有其他问题，请随时联系：[你的手机号/邮箱]"
```

**写修改说明的好处**：审核员会感觉被尊重，二次审核速度通常更快。

---

## 三、二次提交的技巧

| 技巧 | 原因 |
|---|---|
| **在工作日上午提交** | 审核员在工作日处理，早上提交可能当天出结果 |
| **附上修改说明** | 减少审核员重新排查的时间 |
| **修改不要太多** | 改得越多，审核员越需要重新审全部 |
| **保留旧版本截图** | 万一新版本又有问题，可以快速回退 |

---

## 四、如果连续被打回（三次以上）

### 三步自救法

1. **暂停提交**：连续被打回说明你的理解和平台要求有系统性偏差
2. **找已过审的同类产品对比**：打开竞品，逐页对比：他们有的页面你有吗？他们怎么处理权限/支付/隐私的？
3. **去官方社区/论坛提问**：微信开放社区（developers.weixin.qq.com/community）有官方人员回复，贴上你的审核反馈截图，一般能得到准确方向
