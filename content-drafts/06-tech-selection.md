# 节点06：技术选型（零基础专属）

> **面向OPC**：一人公司/独立开发者，想在2026年用AI工具一个人完成从验证到上线的全流程。本文不要求任何编程基础。

---

## 一、先定方向：Web vs 小程序 vs App

技术选型的第一步不是选工具，而是选平台。方向错了，后面全是沉没成本。

### 三平台决策框架

| 维度 | Web应用 | 微信小程序 | 移动App |
|---|---|---|---|
| **学习曲线** | ⭐ 最低 | ⭐⭐ 中等 | ⭐⭐⭐ 最高 |
| **开发到上线** | 1-2周（Vercel部署） | 2-4周（含审核） | 4-8周（含商店审核） |
| **用户获取** | SEO/社交分享/直接链接 | 微信生态自带流量 | 应用商店搜索+付费投放 |
| **支付集成** | Stripe（海外）/ 支付宝网页支付 | 微信支付（JSAPI） | IAP（苹果）/ 各安卓市场 |
| **更新迭代** | 秒级部署，即时生效 | 审核1-7天 | 审核1-3天 |
| **月成本** | $0-20（Vercel+Supabase免费额度） | ¥300认证费/年 + 服务器 | $99 Apple年费 + 服务器 |
| **适合场景** | SaaS工具、内容站、AI应用 | 微信生态内工具、电商、服务预约 | 高频使用、需要推送通知、拍照/定位等硬件能力 |

### 决策口诀

> **你的用户在哪里，平台就在哪里。**

- 用户通过搜索引擎/社交媒体找到你 → **Web**
- 用户就在微信里，你希望他们"扫一扫"就能用 → **小程序**
- 用户需要频繁打开、接收推送、调用摄像头等 → **App**

**OPC铁律**：除非你有明确的理由选择小程序或App，否则一律从Web开始。Web的开发速度最快、迭代成本最低、部署最简单。

## 二、后端正解：为什么OPC只需要Supabase

### "后端"不是服务器

传统认知里，做产品需要：买服务器 → 装Linux → 配Nginx → 装数据库 → 写API。这条路OPC一个人走，至少浪费30天。

**Supabase是什么**：开源的Firebase替代品。一句话——它给了你一个现成的PostgreSQL数据库 + 自动生成的REST API + 用户认证系统 + 文件存储。

### 为什么它是OPC的后端正解

| 传统自建 | Supabase |
|---|---|
| 自己搭PostgreSQL（至少半天） | 创建项目，30秒可用 |
| 手写CRUD API（每个表至少2小时） | 建表后API自动生成 |
| 自己实现JWT鉴权（至少一天） | 内置Auth，支持邮箱/手机/OAuth |
| 自己配置SSL/域名（半天） | 自带HTTPS |
| 数据库备份靠自己写脚本 | 自动每日备份 |
| 扩展靠手动升级服务器 | 按用量自动伸缩 |

### 2026年5月免费额度（足够用到第一个付费用户）

- 数据库：500MB（约10万行普通数据）
- API请求：每月200万次
- 认证用户：每月5万活跃用户
- 存储：1GB文件存储
- 2个免费项目

**突破免费额度之前，你大概率已经有收入了。**

### Supabase的局限（诚实交代）

- 不支持存储过程（用Edge Functions替代）
- 免费项目7天不活跃会休眠（有请求自动唤醒）
- 数据库在云端，无法做本地离线
- 复杂查询性能不如自建专用服务器

**但这些局限对OPC的第一个产品来说，全部不是瓶颈。** 当这些成为瓶颈的那天，你已经成功了。

## 三、AI编码工具矩阵（2026年5月）

选好方向和基础设施后，进入核心问题：**用哪个AI工具写代码？**

2026年5月的AI编码工具已经高度分化，每个工具都有自己鲜明的定位。以下是OPC最相关的五个工具：

### 工具全景对比

| 工具 | 定位 | 最适合 | 月费用 | 学习曲线 |
|---|---|---|---|---|
| **Trae** | 字节跳动出品，中文原生支持，IDE集成 | 国内开发者，中文需求，小程序场景 | 免费（基础）/ ¥199 Pro | ⭐ 低 |
| **Cursor** | AI-first IDE，项目级上下文理解 | 需要深度理解代码库的日常开发 | $20 Pro / $40 Business | ⭐⭐ 中 |
| **GitHub Copilot** | IDE自动补全鼻祖，生态最成熟 | 已有GitHub工作流，需要可靠补全 | $10 Individual / $19 Business | ⭐ 最低 |
| **Claude Code** | 终端CLI代理，自主执行能力最强 | 自动化脚本、测试生成、复杂重构 | 按token用量（Max计划$200/月） | ⭐⭐⭐ 高 |
| **Codex** | OpenAI终端编码代理，开源 | 长任务自主执行、研究型编码 | 按token用量 | ⭐⭐ 中 |

### 逐个深度评测

#### 1. Trae — 国内OPC的首选IDE

字节跳动2025年推出的AI编码工具，内置在自有IDE中。**最大优势是中文理解能力碾压所有竞品。**

- **核心竞争力**：对中文技术文档、微信小程序开发、国内云服务（阿里云/腾讯云）的生态集成远超海外工具
- **典型场景**：用中文描述"做一个微信小程序登录页，包含手机号验证码登录和微信一键登录"，Trae能直接生成符合微信规范的完整代码
- **2026年5月更新**：新增小程序项目模板，支持字节系云服务一键部署
- **弱点**：海外服务（Vercel/Stripe/Supabase）的集成经验不如Cursor和GitHub Copilot丰富
- **费用**：基础版免费，Pro版 ¥199/月（含高级模型调用额度）

#### 2. Cursor — 技术型OPC的日常主力

Cursor是目前AI IDE品类中综合体验最好的产品。它不是"代码补全工具"，而是"AI搭档"。

- **核心竞争力**：Tab补全快如闪电（100ms级）+ Composer多文件编辑 + 项目级上下文（自动索引整个项目结构）
- **代理模式**（2026年5月已成熟）：Cursor Agent可以接收自然语言指令，自主完成"找文件→理解逻辑→多文件修改→运行测试→修复错误"的完整链路
- **最大特色**：`.cursorrules` 文件让你定义项目级AI行为准则，相当于给你的AI搭档写了一本"员工手册"
- **2026年5月价格**：Pro $20/月（500次高级请求），Business $40/月（无限高级请求）
- **弱点**：对国内生态（微信小程序、阿里云）的理解不如Trae
- **适合人群**：愿意花1-2天学习基础概念（什么是变量、什么是函数）的OPC

#### 3. GitHub Copilot — 最安全的选择

Microsoft出品，嵌入VS Code生态。**最大的优势不是功能最强，而是"绝对不会错"。**

- **核心竞争力**：代码补全准确率行业最高（尤其在TypeScript/JavaScript/Python上），企业级代码安全扫描内置
- **Copilot Chat**（2026年已成熟）：在IDE内直接对话，可以选中代码问"这段为什么慢"
- **Copilot Workspace**（2026年新推）：从Issue直接生成完整PR，适合有明确需求的标准化功能开发
- **2026年5月价格**：Individual $10/月（含Chat），Business $19/月（含组织管理）
- **弱点**：代理能力弱于Cursor和Claude Code，只能做单文件级别的修改，做不到跨文件的自主重构
- **适合人群**：完全零基础或者极度保守的OPC（50%以上的Fortune 100公司都在用）

#### 4. Claude Code — 最聪明的"外包工程师"

Anthropic出品的终端CLI工具。**它的定位不是IDE，而是"你雇的一个全天候远程工程师"。**

- **核心竞争力**：超长上下文（200K token），能一次性理解整个中型项目的代码结构、数据库Schema、API路由之间的全部关系
- **自主执行能力**：可以接收"把这个项目的支付模块从Stripe迁移到微信支付"这种级别的指令，自己规划步骤、执行、测试、修复，整个过程可能持续30分钟以上，无需人工干预
- **最佳用途**：不是日常编码，而是：自动化脚本生成、测试套件编写、数据库迁移、代码安全审计
- **2026年5月价格**：按token用量计费，Max计划$200/月（含高用量），Pro计划$20/月
- **弱点**：运行在终端，没有图形界面；对不熟悉命令行的OPC有门槛；持续运行成本可能较高
- **适合人群**：有一定技术基础、需要"重型武器"处理复杂任务的OPC

#### 5. Codex — 开源生态的终端代理

OpenAI维护的开源项目，是Codex CLI的核心引擎。**它和Claude Code定位相似但在成本模型和生态上有本质差异。**

- **核心竞争力**：开源（代码完全可见，可以自己部署到私有环境），非商业用途完全免费，通过API调用各种模型（不绑单一模型供应商）
- **插件生态**（2026年快速发展）：社区贡献了大量Skills和Plugins，覆盖部署、测试、数据库迁移等场景
- **典型场景**："帮我在Supabase上建一个用户表，包含邮箱、密码哈希、创建时间三个字段，然后生成React前端登录组件"——Codex能自主执行完整链路
- **2026年5月**：已支持MCP协议（工具扩展标准），可连接数据库、浏览器、文件系统等外部工具
- **弱点**：社区驱动，稳定性不如商业产品；CLI界面对新手不友好；需要一定的配置成本
- **费用**：本身免费开源，仅需支付调用的模型API费用
- **适合人群**：愿意折腾、注重隐私/可定制性、有一定技术好奇心的OPC

## 四、三条实战路径：按技术水平选择

### 路径一：零基础 / 只懂产品

**核心工具**：Trae + Supabase

**为什么**：
- Trae对中文理解最好，你可以用大白话描述需求
- Supabase让你完全不用碰服务器
- 学习曲线：从注册Trae到看到第一个页面，约30分钟

**OPC实战工作流**：

> **周一上午**：在Trae中新建项目，用300字中文描述你的产品（它叫什么、核心功能是什么、用户从哪里来）
>
> **周一下午**：Trae生成第一个页面。用自然语言调整："这个按钮不够大，改成首页居中，颜色换成#C0392B"
>
> **周二**：在Supabase建一个表（完全图形化操作，不需要写SQL），告诉Trae"帮我连接这个数据库，做一个可以读取数据并展示的页面"
>
> **周三**：部署到线上。把代码推到GitHub，连上Vercel，自动上线

**这条路径的输出质量**：足以让种子用户看到"真的能用的东西"，而不是PPT。

---

### 路径二：会一点基础 / 理解变量和函数

**核心工具**：Cursor + GitHub Copilot

**为什么**：
- Cursor的项目理解能力能帮你维护2-3个页面的完整应用
- GitHub Copilot的自动补全让你写代码像在填表
- 两者的价格加起来$30/月，这是你唯一的"人力成本"

**关键习惯**：

> 1. **建一个 `architecture.md`**，放入项目根目录。用中文写清楚：这个项目有几个页面、数据库有哪些表、核心逻辑是什么。让Cursor每次都读这个文件作为上下文。
>
> 2. **每次改完代码让AI写commit message**："帮我总结这次的改动，写一条git commit message"
>
> 3. **遇到bug先截图**，把截图+报错信息一起扔给Cursor："这个页面点击按钮后报了这个错，帮我修"

---

### 路径三：有经验的开发者

**核心工具**：Cursor + Claude Code + Codex

**为什么三件套**：
- Cursor做日常开发（写功能、改UI、调接口）
- Claude Code做重型任务（数据库迁移、批量重构、生成测试）
- Codex做补充和探索（新想法快速验证、开源工具链集成）

**周工作流示例**：

> **周一**：Cursor里用中文写本周的spec文档，让Cursor扫描全项目，给出一份"本周可执行任务清单"
>
> **周二上午**：Cursor执行3-4个小任务（用户反馈的bug、UI微调）
> **周二下午**：Claude Code执行数据库迁移任务（"把用户表的`phone`字段拆成`country_code`和`phone_number`两个字段，同步更新所有相关API和前端组件"）
>
> **周三**：Codex探索一个新想法（"帮我在新分支上创建一个WebSocket实时通知的原型"），验证可行后合并
>
> **周五**：Cursor扫描本周所有commit，自动生成周报

## 五、技术可行性验证

工具选得再好，也得先验证——你的核心功能在技术上能不能实现。

### 核心原则：只验证"唯一的那个东西"

OPC在验证阶段最容易犯的错：先做登录系统、用户权限、后台管理、设置页面……然后累死在半路上。

**验证阶段只需要验证一件事**：你的产品核心算法/逻辑，能不能把输入变成输出。

| 该做的 | 不该做的 |
|---|---|
| 一个上传按钮 + 分析函数 + 结果展示 | 完整的用户登录系统 |
| 一段能把中文问题翻译成SQL的提示词 | 用户角色权限管理 |
| 30行Python验证推荐算法准确率 | 后台CMS管理系统 |

**判断标准**：能不能用一句话描述你的核心功能？如果能——继续。如果不能——说明你还没想清楚，回去继续裁剪。

### "人造现实"验证法：用造假装一个真的

不需要先构建完整后端。用这三个递进层次：

**L1：录屏原型（半天）**
用任何录屏工具录一段操作演示。发给目标用户问："如果你有这个，你会用吗？"——零代码验证需求。

**L2：硬编码响应（一天）**
前端做完整，但后端所有返回值都是写死的。用户点击"分析"，永远返回同一份模拟结果。验证的是交互流程。

**L3：绿野仙踪模式（两天）**
前端完整 + 用户提交后你手动用AI处理 + 粘贴结果回去。在用户看来系统是"自动"的，实际你是幕后的法师。

### 72小时微型实验

- **招募**：5-10个正在经历你解决的问题的人（不是"对品类感兴趣的"，是"现在就在痛"的）
- **观察**：不要问"你觉得怎么样"，而是看——他能不能不问你就理解第一步操作？有没有出现超过10秒的停滞？
- **边界**：72小时，5-15人，一个核心行为完成率。这是OPC最残酷也最诚实的验证边界。

### 硬核停止指标

| 指标 | 红线 | 达标行动 |
|---|---|---|
| 无干预完成率 | ≥80%（5人至少4人独立完成核心动作） | 不达标 → 重新设计交互 |
| 单位毛利 | API调用成本 < 目标售价的30% | 不达标 → 技术路线失败，换方案 |
| 响应延迟 | 核心功能返回 < 3秒（非实时场景） | 超时 → 优化或换技术方案 |

**如果三条标准全部通过** → 验证通过，可以进入MVP开发。
**有任何一条不过** → 果断终止。沉没成本不是继续的理由。

## 六、工具订阅成本控制

2026年AI工具订阅很容易月支出超过$200。OPC需要用"将军思维"管理工具成本。

### 成本分层策略

| 工具层级 | 策略 | 示例 |
|---|---|---|
| **核心常驻** | 始终订阅，每月固定 | Cursor Pro $20/月 |

### 成本红线

OPC的前六个月，总工具成本控制在 **¥300/月** 以内。超过这个数，说明你可能在为"感觉很厉害"的工具付费，而不是为"真正创造收入"的工具付费。

### 每季度审查

每三个月问自己：
- 这个工具我上月打开了几次？
- 如果停用它，有什么是其他工具做不到的？
- 它的免费版/替代品现在能做到什么程度？

## 七、工具绑定风险与迁移预案

### 最大的风险：你根本不知道你的应用怎么跑起来的

2026年有大量"描述即生成"的工具。危险在于——它们在让你30分钟做出一个产品的同时，也让你对产品的技术细节完全失明。

**真实案例**：2025年底，某OPC用AI工具生成了一整套SaaS后端。半年后想迁移到自建服务器，发现数据库结构全嵌在平台私有方案里，迁移成本几乎等于重写。

### 防锁死三原则

**原则一：第一天就下指令**

> 在任何AI工具中，第一次让它生成代码时就加上这段话：
>
> "请用标准、通用的方案实现。数据库请用PostgreSQL标准SQL语法，鉴权请用JWT标准方案，避免任何平台专属函数或私有API。"

**原则二：理解核心流程**

不用会写，但要会读。每周挑一段AI生成的业务逻辑代码，用Cursor的"解释这段代码"功能理解它。你不需要成为程序员，但需要能在出问题时，用一句话准确描述问题给AI。

**原则三：保持数据主权**

- 数据库用Supabase（开源，随时可以导出标准SQL）
- 代码托管在GitHub（你拥有完整的git历史）
- 域名在你自己的注册商手里（不要用平台送的临时域名）
- 不要在任何单一平台上同时绑定代码、数据库和域名

## 总纲

2026年是OPC利用AI编码实现"单人业务规模化"的最后窗口期。工具已足够成熟——接下来的问题是：你的角色是否已经完成了从"写代码的人"到"指挥AI军团完成产品的人"的转变。

**选型四步法**：
1. 先定平台（Web优先）
2. 再定后端（Supabase）
3. 匹配工具（按技术水平选路径）
4. 验证可行性（72小时，5个人）

> 工具不再是辅助。工具就是你的团队。你唯一的任务是：发出正确的指令。

## 八、国内OPC网络现实：海外服务连接方案

> **第一道门槛不是代码，是网络。** 以下基于2026年5月中国大陆实际网络环境。

### 基础设施可达性

| 服务 | 直连可用？ | 说明 |
|---|---|---|
| **Supabase Cloud** | ❌ 不稳定 | 托管于AWS海外节点，国内访问延迟高、不稳定 |
| **Vercel** | ⚠️ 偶尔可用 | 海外CDN，国内部分地区可访问 |

### OPC实战建议

**如果你在国内，网络条件有限**：

> 首选 **Trae** 作为主力IDE。目前唯一一个在国内部署、中文原生、基础版免费的AI编码产品。搭配 Gitee（代码托管）+ 阿里云/腾讯云部署 + 自建Supabase，完全走国内生态完成从开发到上线的全流程。

**如果你有能力优化海外网络访问**：

> 很多独立开发者在日常工作中会为自己的开发环境配置网络优化方案——这是行业内的常见做法。Cursor + Claude Code + Supabase Cloud + GitHub + Vercel 是能力最强的技术栈组合，但前提是你能为开发环境提供稳定的海外网络连接。这类方案的技术细节不在本文讨论范围，建议自行了解。

**折中方案（推荐）**：

> 日常开发用 Trae（免费+流畅），遇到跨文件重构、测试生成等复杂任务时切换到 Claude Code 按量使用（用完即关），代码同时推送到 GitHub 和 Gitee 形成双备份。这种组合兼顾了日常效率和关键时刻的能力上限。
