# 节点31：数据监控

> **面向OPC**：你的产品上线了，现在每天都有数据进来。但一个人盯不过来——本章只用看3个数字，配一个5分钟就能搭好的监控系统。不需要数据分析师，不需要SQL。

---

## 一、OPC数据哲学：只盯三件事

### 你不需要看的东西（先列出来，省得你焦虑）

| 你常见的焦虑 | 为什么不需要看 |
|---|---|
| "昨天地域分布里新疆突然多了3个用户，我要不要研究？" | 一人产品的小样本波动没有任何决策意义 |
| "平均停留时长从上月2分18秒降到2分07秒了" | 11秒的差异不是趋势，是噪声 |
| "跳出率从62%变成65%了" | 3%在小样本下不构成任何信号 |
| "用户画像里25-30岁占比下降了2%" | 你只服务几百个人时，画像没有统计意义 |
| "需要建一个数据大屏实时监控" | 你一个人盯不了大屏，关键是关键时刻能发现问题 |

### OPC唯一需要盯的三个数

```
┌──────────────────────────────────────────────────────┐
│                    OPC数据仪表盘                       │
│                                                      │
│  ① 日活用户（DAU）  ← 你的产品今天有没有人用          │
│     今天：___  昨天：___  上周同期：___                │
│                                                      │
│  ② 核心功能使用率  ← 用户有没有用到产品的灵魂功能      │
│     完成率：___%  目标：>60%                          │
│                                                      │
│  ③ 留存率  ← 用户用完会不会回来                       │
│     次日留存：___%  (目标>30%)                        │
│     7日留存：___%   (目标>15%)                        │
│     30日留存：___%  (目标>10%)                        │
│                                                      │
└──────────────────────────────────────────────────────┘
```

### 为什么这三个就够了

| 指标 | 它告诉你 | 异常时意味着 |
|---|---|---|
| **DAU** | 产品还活着吗 | 连续3天腰斩 → 服务器挂了/支付崩了/被微信封了 |
| **核心功能使用率** | 用户用对了吗 | 注册100人但核心功能只有3人用过 → 引导太差或功能不对 |
| **留存率** | 产品有价值吗 | 次日留存<20% → 用户第一分钟就决定"这东西没用" |

### 不需要拆维度、不需要建漏斗、不需要A/B测试

你不是字节跳动。你有300个用户，拆10个维度后每个格子只有3个人。3个人的数据变化没有任何统计学意义。

**OPC数据分析的原则是：盯住命门，忽略其他。**

## 二、GA4 接入5分钟教程（2026年5月界面）

### 什么是GA4

Google Analytics 4，谷歌的免费网站分析工具。**2026年最实用的免费分析方案。**

### 注册和接入

**第1步：注册GA4账号（1分钟）**

1. 打开 [analytics.google.com](https://analytics.google.com)
2. 用Google账号登录（没有的话注册一个，免费）
3. 点击"创建账号" → 输入账号名称（比如你的产品名）
4. 点击"创建媒体资源" → 输入产品名 + 时区选"中国标准时间"
5. 点击"创建" → 选择"网站"平台
6. 输入你的网站URL → 点击"创建数据流"

**第2步：获取测量ID（30秒）**

数据流创建后，你会看到一个"测量ID"，格式为 `G-XXXXXXXXXX`。复制它。

**第3步：粘贴代码（2分钟）**

在网站每个页面的 `<head>` 标签内，粘贴以下代码：

```html
<!-- Google tag (gtag.js) -->
<script async src="https://www.googletagmanager.com/gtag/js?id=G-XXXXXXXXXX"></script>
<script>
  window.dataLayer = window.dataLayer || [];
  function gtag(){dataLayer.push(arguments);}
  gtag('js', new Date());
  gtag('config', 'G-XXXXXXXXXX');
</script>
```

替换 `G-XXXXXXXXXX` 为你的测量ID。

**第4步：验证（1分钟）**

部署后，打开GA4 → 报告 → 实时。用手机打开你的网站，30秒内应该能在实时报告中看到"1个活跃用户"。

### 国内注意事项

⚠️ GA4依赖Google服务器，**国内用户直接访问可能不稳定**。如果你是用Trae做开发、主要面向国内用户，建议GA4 + 百度统计双接入（见下一章）。

**补救方案**：Vercel部署的网站可以开一个中间代理，把GA4请求转发到自己的域名上。如果不会配，直接用百度统计替代。

## 三、百度统计接入：国内用户必备

### 为什么需要百度统计

- 服务器在国内，加载速度快（一秒之内）
- 中文后台，无学习曲线
- 自动生成热力图（看到用户点了哪里）——这是免费功能
- 微信小程序也可接入

### 接入步骤（3分钟）

**第1步**：打开 [tongji.baidu.com](https://tongji.baidu.com)

**第2步**：用百度账号登录 → 点击"添加站点"

**第3步**：填入你的网站域名 → 获取JS代码

**第4步**：将代码粘贴到所有页面的 `</head>` 之前：

```html
<script>
var _hmt = _hmt || [];
(function() {
  var hm = document.createElement("script");
  hm.src = "https://hm.baidu.com/hm.js?你的统计ID";
  var s = document.getElementsByTagName("script")[0]; 
  s.parentNode.insertBefore(hm, s);
})();
</script>
```

**第5步**：等5分钟，打开百度统计后台 → "实时访客"，用手机访问你的网站验证。

### 百度统计 vs GA4

| 维度 | GA4 | 百度统计 |
|---|---|---|
| 服务器位置 | 海外（国内可能慢） | 国内（秒开） |
| 免费 | ✅ | ✅ |
| 热力图 | 需付费/第三方 | ✅ 内置免费 |
| 事件追踪 | 灵活但学习成本高 | 简单但不够灵活 |
| 中文支持 | 有中文界面 | ✅ 原生中文 |
| 小程序 | ❌ | ✅ 可接入 |
| 数据导出 | ✅ | 有限制 |

**OPC推荐**：两者都接入。GA4做主分析（数据更灵活），百度统计做热力图和国内用户确认。

## 四、微信小程序数据分析接入

### 小程序天生就有数据

微信小程序不需要额外接入统计——微信后台自带数据分析：

**入口**：登录 [mp.weixin.qq.com](https://mp.weixin.qq.com) → 左侧菜单 → "统计"

### 小程序自带的关键指标

| 菜单 | 核心数据 | OPC需要看吗 |
|---|---|---|
| **用户分析** | 日活、新增、留存 | ✅ 必看 |
| **访问分析** | 访问深度、停留时长 | ⚠️ 偶尔看 |
| **页面分析** | 各页面访问量、退出率 | ✅ 核心功能页面必看 |
| **来源分析** | 用户从聊天/朋友圈/搜索进入 | ⚠️ 偶尔看 |
| **实时统计** | 当前在线、今日累计 | ✅ 上线第一周每天看 |

### 小程序 + 百度统计

微信自带统计有一个盲区：**看不到热力图**（用户具体在页面上点了哪里）。

补救方案：小程序可以使用百度统计的[小程序SDK](https://mtj.baidu.com)（在百度统计后台 → 小程序应用 → 添加应用获取AppKey）。

### 小程序 + GA4

微信小程序**不能直接**接入GA4。但可以通过自定义上报实现：

1. 在小程序后台 → 开发 → 开发设置 → 服务器域名 → 添加 `https://www.google-analytics.com`
2. 在自己的服务器上搭一个数据转发接口（GA4的measurement protocol）

**建议**：如果只是为了看三个数，小程序自带统计 + 百度统计足够。不需要折腾。

## 五、不要看的数据库清单（避免分析瘫痪）

### 这些数据看多了只会让你焦虑，不会让你变聪明

| 数据 | 为什么不要盯 | 什么时候才需要看 |
|---|---|---|
| **PV/UV每小时波动** | 小产品的小时数据是纯噪声 | 日均UV > 1000时 |
| **设备型号分布** | 除非你的产品有兼容性问题，否则没用 | 大量用户反馈某机型闪退 |
| **浏览器分布** | 一二线城市Chrome 80%+，不需要操心 | 收到IE/旧版浏览器bug反馈 |
| **地域分布** | 你一个人的产品不需要按城市做市场策略 | 考虑投本地广告时 |
| **用户年龄/性别** | 微信和GA4的画像精准度远不如你以为的 | 准备融资展示时做PPT用 |
| **新老用户比** | 在500 DAU以下没有统计意义 | DAU > 1000 |
| **会话时长** | 好的产品用户用30秒就走了（工具属性），差的产品用户研究半天（看不懂） | 结合核心功能使用率一起看 |
| **跳出率** | 单页应用、工具型产品的跳出率天然高 | 配合转化漏斗看 |

### OPC正确做法

1. **每周一看**：DAU、核心功能使用率、留存率。三个数，看一眼，30秒完毕。
2. **每月一总结**：把四周的数据放进Excel，画出折线图。如果连续四周持平或上涨 → 不看细节。如果连续四周下跌 → 回到"数据异常诊断流程"（见下章）。
3. **其余时间**：不要打开GA4。去做推广、做产品、聊用户。

## 六、数据异常诊断流程

### 当DAU突然腰斩（连续3天）

```
① 检查服务器
   → Vercel dashboard 看部署状态
   → Supabase dashboard 看API是否正常
   → 用手机亲自访问一次

② 检查支付
   → 支付是否还能正常拉起？
   → 有无支付回调失败通知？

③ 检查封禁
   → 微信有没有提示"已停止访问该网页"？
   → 域名有没有被墙？
   → 小程序有没有被下架/限流通知？

④ 检查流量来源
   → 百度统计→来源分析→看看哪个渠道掉量了
   → 如果你靠SEO，检查搜索排名有没有掉
   → 如果你靠社群，检查群里有没有人说了负面

⑤ 找3个活跃用户直接微信问
   → "这两天用我们的产品有什么不对劲吗？"
```

### 当核心功能使用率持续偏低（<30%）

```
① 检查引导
   → 新用户进来第一屏能直接看到核心功能入口吗？
   → 还是藏在菜单深处？
   → 用一个非技术朋友测试：打开产品，问他能在10秒内找到核心功能吗

② 检查功能名
   → 功能按钮上写的文案，用户能看懂吗？
   → A/B测试两个按钮名（比如"立即分析"vs"上传文件"）

③ 检查是否有竞品
   → 用户有没有直接告诉你"我觉得XX更好用"？
   → 去知乎/小红书搜你的品类名，看最新评论
```

### 当留存率持续低迷（次日<20%）

```
留存率是你的产品价值的唯一客观评分。

如果不是技术bug导致的，那就是一件事：
  → 你的产品没有解决用户真正的问题。

验证方法：
  → 给上个月注册的10个用户发红包，做5分钟微信语音
  → 问："为什么后来不用了？"
  → 听他们的原话，不要听"挺好用的就是没时间"
  
真实的答案通常是：
  "好用，但没觉得不用会怎样"
  "和朋友推荐XX了，他说YY更好用"
  "注册完不知道下一步该干嘛"
```

## 总纲

Google Analytics、百度统计、微信后台——三套数据系统，对OPC来说**只有三个数字需要每周看一眼**：

| 数字 | 含义 | 红线 |
|---|---|---|
| 日活 | 产品还活着吗 | 连续3天掉50% → 立刻排查 |
| 核心功能使用率 | 用户用对了吗 | <30% → 改引导 |
| 次日留存 | 产品有用吗 | <20% → 回去做用户访谈 |

> 你不是字节跳动的数据分析师。你有300个用户时做30个维度的交叉分析，每个格子只有3个样本——那不是分析，是自我欺骗。
