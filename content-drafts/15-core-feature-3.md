# 节点15：核心功能3开发

> **面向OPC**：核心功能1让用户"能用"，核心功能2让用户"留下来"，核心功能3让用户"带人来"。这是产品从工具变成平台的最后一块拼图。

---

## 一、核心功能3的定位：闭合体验环

### 不是"再多做一个功能"

核心功能3 ≠ 功能堆砌。它的使命是**把前两个功能串成一个用户无法离开的环**。

### 产品闭环模型

```
用户使用核心功能1 → 核心功能2展示成果 → 核心功能3让成果扩散/变现
        ↑                                              │
        └──────────────── 用户因此回来再用 ──────────────┘
```

### 四种典型的闭环形态

| 产品类型 | 闭环形态 | 核心功能3长什么样 |
|---|---|---|
| **AI工具** | 生成→展示→分享 | "一键生成分享卡片"，用户发朋友圈/推特，带来新用户 |
| **SaaS** | 操作→报表→通知 | "每周自动发送数据周报到邮箱"，用户不看产品也会被拉回来 |
| **内容产品** | 浏览→收藏→订阅 | "关注/订阅+新内容推送"，用户变成日活 |
| **电商/服务** | 浏览→收藏→提醒 | "降价提醒/库存提醒/复购提醒"，把一次购买变持续复购 |

### 选型决策口诀

> 如果你的产品强在**社交属性** → 选分享裂变  
> 如果你的产品强在**数据价值** → 选自动报告  
> 如果你的产品强在**内容更新** → 选订阅推送  
> 如果你的产品强在**交易转化** → 选智能提醒

**只选一个。** 一次只做一种闭环。

## 二、四大闭环形态的OPC实现方案（2026年）

### 方案A：分享裂变（适合AI工具/内容产品）

**一句话价值**：每个用户变成你的免费推广渠道。

**最轻量实现**：

```javascript
// html2canvas 生成分享卡片（2026年主流方案）
import html2canvas from 'html2canvas';

async function generateShareCard() {
  const canvas = await html2canvas(document.getElementById('result-card'));
  const imageUrl = canvas.toDataURL('image/png');
  // 触发浏览器分享API（微信/浏览器原生分享）
  if (navigator.share) {
    await navigator.share({ title: '我的OPC分析报告', url: imageUrl });
  }
}
```

**关键数据**：html2canvas 是2026年最成熟的网页截图库，GitHub 30k+星标。3行代码即可把任何DOM节点生成图片。

**避坑指南**：
- 分享卡片上必须带你的产品名+域名（否则白给别人引流）
- 卡片设计要好看——用户不会分享一张丑图
- canvas尺寸建议750×1000（微信分享最佳比例）

### 方案B：自动报告（适合SaaS/数据分析工具）

**一句话价值**：用户不来产品，产品主动找用户。

**最轻量实现**：

```javascript
// Supabase Edge Functions + Cron 定时触发
// 每周一早上8点自动发送上周数据摘要
import { Resend } from 'resend';  // 2026年最主流的事务邮件API

const resend = new Resend(process.env.RESEND_API_KEY);
await resend.emails.send({
  from: 'OPC节点百科 <report@你的域名.com>',
  to: user.email,
  subject: '你的上周数据报告已生成',
  html: `<h1>上周你完成了 ${weeklyCount} 次分析</h1>...`
});
```

**关键数据**：Resend 是2026年开发者首选邮件API。免费额度每天100封，足够用到1000个用户。

**避坑指南**：
- 第一版只做"周报"，不要做"日报"（日报打开率不到5%，周报打开率40%+）
- 邮件标题必须包含一个数字（"你上周完成了247次分析"），打开率比无数字标题高3倍
- 用真实发件人域名（`@你的域名.com`），不要用gmail/qq等个人邮箱

### 方案C：订阅推送（适合内容产品/社区）

**一句话价值**：用户订阅后，每次更新自动通知，不依赖用户"想起你"。

**最轻量实现**：

```javascript
// 2026年浏览器原生Push API + Service Worker
// 不需要安装任何第三方SDK
self.registration.showNotification('OPC节点百科', {
  body: '节点24"域名购买与ICP备案"已更新',
  icon: '/icon-192.png',
  data: { url: '/nodes/24-domain-icp/' }
});
```

**避坑指南**：
- Web Push在iOS上的支持2026年才刚完善（iOS 18.4+），但Android和桌面端全覆盖
- 推送频率不超过每周2次，否则用户会关掉通知权限
- 微信小程序用"服务通知"模板消息替代Web Push

### 方案D：智能提醒（适合电商/服务预约）

**一句话价值**：把"用户想到才用"变成"产品替用户记得"。

**2026年实现**：Supabase Cron（2026年3月上线）+ 数据库定时任务。

```sql
-- Supabase Cron: 每天早上9点扫描需要提醒的用户
select cron.schedule(
  'daily-reminder',
  '0 9 * * *',
  $$ 
    select * from users 
    where last_active < now() - interval '7 days'
    and reminder_enabled = true
  $$
);
```

## 三、三大功能协同检查（上线前必看）

| 检查项 | 通过标准 |
|---|---|
| **数据一致性** | 核心功能1产生的数据，核心功能2和3能直接读取，不需格式转换 |
| **跳转体验** | 从功能1→功能2→功能3的路径，每一步都有明显的"下一步"入口 |
| **权限统一** | 一个用户登录后，三个功能区都能访问（不需要分别登录） |
| **设计统一** | 三个功能区的导航栏、配色、字体保持一致 |
| **错误隔离** | 核心功能3挂了，不影响核心功能1和2的使用 |

## 四、一个真实案例：OPC闭环的形成过程

假设你的产品是"AI简历优化工具"：

| 阶段 | 功能 | 用户行为 |
|---|---|---|
| 核心功能1 | 上传简历→AI分析→返回优化建议 | "有用，改完就关了" |
| 核心功能2 | 优化前后的对比评分 + 历史记录 | "能看到自己从45分变78分，挺好的" |
| 核心功能3（闭环） | "生成简历分享海报，发朋友圈领取免费优化额度" | 用户发朋友圈 → 朋友扫码 → 新用户注册 |

**闭环效果**：每10个使用核心功能3的用户，带来3-5个新注册用户。零广告费。

## 五、常见翻车

| 翻车方式 | 后果 | 预防 |
|---|---|---|
| **三个闭环全做** | 哪个都是半成品，一个都不闭环 | 看本文第二节，只选一种 |
| **分享卡片忘记加水印** | 别人的朋友圈只有内容，没有你的产品名 | 卡片底部必须加"由 [产品名] 生成" |
| **邮件进了垃圾箱** | 周报白写，用户永远看不到 | 用Resend/阿里云企业邮，配置SPF+DKIM |
| **推送太频繁** | 用户关闭通知权限，以后再也推不了 | 每周≤2次 |

## 六、检查清单

- [ ] 闭环形态已选定（只选一种：分享/报告/推送/提醒）
- [ ] 分享卡片上有产品名+域名
- [ ] 邮件使用企业域名发件人（非个人邮箱）
- [ ] 推送频率控制在每周≤2次
- [ ] 三个功能区的数据能互通、跳转流畅、设计统一
- [ ] 核心功能3崩溃不影响前两个功能
